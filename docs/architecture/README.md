# Архитектурный атлас

Четыре листа вместо одного графа зависимостей.

**Числа в нём верны на один коммит и стареют молча.** За первый же день под
атласом закрылись `#146` и `#147`, а в каталоге появилась база узумаки —
документ при этом не изменился ни на символ и выглядел свежим. Поэтому у атласа
есть свой сторож: [`atlas-facts.py`](atlas-facts.py) меряет числа заново,
сверяет со слепком и говорит, **на каком листе** править каждое расхождение.

```sh
python3 docs/architecture/atlas-facts.py             # что разошлось и где править
python3 docs/architecture/atlas-facts.py --snapshot   # после правки листов
```

Меряет через `git show <ref>:<файл>`, а не по рабочему каталогу: над «Ролльней»
работает вторая сессия, и замер с полусохранённого файла не соответствует ни
одному состоянию проекта. Слепок поэтому всегда привязан к коммиту, который
можно назвать вслух, и он же печатается в шапке страницы.

**Смотреть:** [`docs/reports/architecture-atlas.html`](../reports/architecture-atlas.html)
— самодостаточная страница, листы вшиты внутрь, файл можно переслать или открыть
с диска. На Pages: `newyurk.github.io/rollery/docs/reports/architecture-atlas.html`.

## Почему четыре, а не один

Граф всех зависимостей рисуется за минуту и бесполезен: двадцать файлов, полторы
сотни связей и ни одного места, где взгляд остановится. Полезен не полный чертёж,
а чертёж **под решение** — и тогда половину связей надо не нарисовать, а
сознательно убрать.

Поэтому у каждого листа записано, чего он **не** показывает. Это не оговорка,
а конструкция: как только лист начинает показывать «ещё и вот это», он перестаёт
отвечать на свой вопрос.

| лист | одно решение | чего нарочно нет |
|---|---|---|
| [`01-system-map.d2`](01-system-map.d2) | Я пишу новое — в какую зону это кладётся и кого ей можно звать? | ни одной обратной стрелки; связей между файлами |
| [`02-danger-edges.d2`](02-danger-edges.d2) | Какую связь резать первой? | ни одной здоровой связи |
| [`03-one-life-path.d2`](03-one-life-path.d2) | Я вставляю сюда шаг — что он тронет? | ветвлений, ошибок, других режимов |
| [`04-target-migration.d2`](04-target-migration.d2) | Какой шаг делать следующим и чем докажу, что не сломала? | пересказа доменного контракта |

Целевая архитектура целиком — [`docs/domain-contract.md`](../domain-contract.md)
§4, §8, §11. Атлас её не заменяет и не пересказывает: он показывает **порядок,
цену и доказательство**.

## Что здесь лежит

```
_style.d2                  общая палитра и классы, импортируется каждым листом
01…04-*.d2                 сами листы — исходники, правятся как код
svg/                       экспорт для просмотра; ПЕРЕЗАПИСЫВАЕТСЯ сборкой
atlas-facts.py             сторож свежести: числа, якоря, статусы задач
atlas-facts.json           слепок на коммите; пересобирается --snapshot
atlas.template.html        шаблон страницы; правится ОН, а не результат
build-atlas-page.py        шаблон + листы → docs/reports/architecture-atlas.html
build-atlas-excalidraw.py  → rollery-atlas.excalidraw, карта для обсуждения
rollery-atlas.excalidraw   результат; правится генератором, а не рукой
build.sh                   всё сразу
geometry-call-audit.md     аудит вызовов геометрии (31.08), отдельная работа
```

## Пересобрать

```sh
brew install d2          # один раз
./build.sh               # все листы + карта + страница
d2 --watch 02-danger-edges.d2   # живая правка: браузер обновляется на сохранении
```

## Карта для обсуждения

[`rollery-atlas.excalidraw`](rollery-atlas.excalidraw) — одна поверхность
на весь разговор: слева что есть, посередине что красное, справа куда едем.
Зелёный пунктир справа налево читается как «этот шаг гасит этот узел».
Внизу оставлено пустое место под два вопроса, которые решает владелец.

Открывается: [excalidraw.com](https://excalidraw.com) → Open → выбрать файл.
Или расширение «Excalidraw» в VS Code. Данные никуда не уходят.

**Правится генератором, а не рукой.** Файл — это JSON на несколько тысяч строк
с id, seed и привязками стрелок; рука в нём не живёт, а следующая пересборка
сотрёт правку. Менять надо `build-atlas-excalidraw.py`.

## Четыре грабли, на которые я уже наступила

Записаны здесь, чтобы следующая правка не потратила на них время заново.

1. **Символ `|` внутри `|md …|` обрывает блок.** Строка
   `` Ключ кеша — `S.base + '|' + wrapKey` `` роняла компиляцию с ошибкой
   на сорок строк ниже. Лечится удлинением ограничителя: `||md … ||`.

2. **Markdown не переносится сам.** Абзац без жёстких переносов растягивает узел
   во всю длину, и лист превращается в ленту — лист 2 в первой редакции вышел
   19 702 px шириной. Поэтому каждая строка внутри `|md …|` кончается обратной
   косой: это жёсткий перенос markdown, и он виден в исходнике (в отличие от двух
   пробелов на конце строки, которые редактор молча срежет).

3. **Многострочная подпись контейнера кладётся поверх детей.** d2 не резервирует
   под неё место. Подпись контейнера — короткая строка в кавычках; описание
   уезжает внутрь отдельным узлом класса `note`. Обычный (не-md) блок ещё хуже:
   переносы схлопываются, и весь текст ложится в одну строку друг на друга.

4. **`&` внутри data-URI нельзя оставлять как есть** (поймал владелец глазами, 01.09).
   Символ законный для URI — но URI живёт внутри HTML-атрибута, а парсер раскрывает
   сущности прямо в значении атрибута: `&lt;` из SVG превращался в голый `<`, SVG
   переставал быть валидным XML, и картинка **молча** не грузилась — ни ошибки
   в консоли, ни следа в вёрстке. Упали ровно те два листа, где в тексте есть
   `` `<script>` `` — 2 и 4. Лист 3 с `&#39;` выжил случайно: апостроф XML не ломает.
   Теперь `&` и `"` кодируются всегда, а сборка сама проверяет round-trip
   и падает, если строка не переживает разбор HTML.

## Когда код разойдётся с чертежом

Править `.d2`, а не SVG: SVG перезаписывается сборкой. Цифры на листе 2 —
это `grep -c`, команды записаны в шапке самого файла, пересчитываются за секунду.

Атлас **не заводит новых утверждений о модели**: всё, что на нём написано,
взято из кода, из `STATE.md` или из issues и ссылается на файл и строку.
Если лист расходится с кодом — прав код.
