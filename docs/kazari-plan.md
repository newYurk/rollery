# От «Ролльни» к симулятору кадзари макидзуси

Направление, присланное владельцем 26.08.2026 вместе с пятым ревью кода.
Сохранено для последующего разбора и реализации.

**Статус 29.08.2026:** этап 3 (карта высот) в работе — рис и
начинка — два поля, вытеснение в стороны, канавка (#30 закрыт; остатки #31,
#32; корень — #1). Маски (этапы 2 и 5, плюс поздние 6–8) заведены как issue
#53; этап 4 (computeCore) — issue #2; профиль сечения вдоль оси — issue #10.

Кадзари макидзуси (飾り巻き寿司) — декоративные роллы, где раскладка на листе
рассчитана так, чтобы в срезе получился рисунок: цветок, панда, иероглиф.
Это ровно то, к чему игра идёт сама: люди делятся альбомами и складывают из срезов
картины — решение владельца от 25.08 (`RESULT.md`).

---

## Главная идея направления

**Переход от прямоугольных патчей к произвольным маскам и картам высот.**

Сейчас каждая начинка — прямоугольник с полем `rot`, а стопка считается через
граф пересечений габаритов. Для узора этого мало: нужно класть ингредиенты
кругами, лентами, ломаными — и рисовать их прямо на листе.

## Этапы (формулировка ревьюера, сокращённо)

### Этап 1. Логические ошибки и базовая оптимизация
Пустой центр спиральных баз, копирование списка перед `restack`, `oneTurn` и
длина листа, кламп `zn`, кэш `patchSRange` и карт материалов.

> **Статус на 26.08 — половина уже закрыта, см. сверку ниже.**

### Этап 2. Произвольные формы начинок — маски
Новый тип патча: **маска** — битовая карта на листе (`Uint8Array` / `ImageData`),
плюс поле `maskScale`. `patchSRange` для маски возвращает диапазон по габариту,
`heightAt` и `matAt` читают бит маски. Инструменты рисования: кисть, заливка,
фигуры. Игрок рисует начинку прямо на нори.

### Этап 3. Послойность произвольных форм — карта высот
Для произвольных форм перекрытие через прямоугольники не работает. Перейти к
растровой **карте высот** на листе: в каждой точке (u, v) хранится высота стопки.
`restack` переписывается на заливку в общую карту с учётом порядка; `stackTopAt`
становится чтением массива, то есть заодно и быстрым.

> Здесь же естественно закрывается **отложенный «профиль сечения вдоль оси»**
> (`docs/ideas.md`, ⚑): карта высот по (u, v) — это и есть то самое, чего сейчас
> не хватает клубнике, креветке и авокадо.

### Этап 4. Физика скручивания
Сжимаемость **на каждый ингредиент** вместо одного глобального `beta` (огурец
жёсткий, рис мягкий). `computeCore` под маски: численное интегрирование вместо
предположения о прямоугольнике.

> Совпадает с подтверждённой находкой валидации: `inCore` принципиально не может
> быть булевым флагом на патч (`docs/archive/review-validation.md`, пункт 6).

### Этап 5. Интерфейс художественной раскладки
Кисть, ластик, фигуры, заливка, выбор толщины. Панель слоёв (порядок, скрытие,
блокировка). Превью нескольких срезов сразу, чтобы видеть узор по длине ролла.
Анимация скрутки с отменой. Экспорт картинки высокого разрешения.

### Этап 6. Обучение и подсказки
Встроенные шаблоны (цветы, звёзды) с возможностью правки. Подсказки «как положить,
чтобы получилось». Режим свободного творчества без ограничений.

### Этап 7. Производительность для сложных раскладок
Web Workers для карт материалов и рендера. Кэш `buildModel`. На телефоне —
пониженное разрешение рендера при сохранении чёткости превью.

### Этап 8. Дополнительно
3D-вид ролла. Подсказки по традиционным узорам. Пазл с поддержкой масок.

## Сверка Этапа 1 с тем, что уже сделано 26.08

Пятое ревью писалось по коду до дневных правок. Три пункта из шести закрыты,
один устарел. **Не делать заново.**

| Пункт ревью | Что с ним на самом деле |
|---|---|
| 1.1 Пустой центр спиральных баз | **Подтверждено** независимой валидацией. Правка известна и в одну строку: `if (r < coreR) return m.core ? coreMaterial(...) : { cls: 'core' };`. Ждёт применения |
| 1.2 Мутация исходного списка | **Подтверждено частично.** Мутация и нестабильный ключ — да. А вот утечка `inCore` в исходный список **не воспроизвелась**, хотя её нашли трое ревьюеров из четырёх |
| 1.3 `turns` и `oneTurn` для суши | **Устарело.** Базы перестроены: вместо `sushi` — `hoso` (полулист 10,5 см) и `futo` (целый лист 21 см), длина задаётся физически через `sheetCm`, `oneTurn` снят. Витки теперь выводятся из листа, а не наоборот |
| 1.4 `coreMaterial` для `paint` | Ревьюер сам пришёл к «ок» по ходу разбора. Отдельная валидация подтвердила: краска в ядре **рисуется** через `coreMaterial` — механизм, описанный в другом ревью, был неверен |
| 1.5 `sampleWind` при `lastIdx` | **Не воспроизвелось.** `f` зажат охранником на той же строке, ревьюер его не учёл. Закрыто |
| 1.6 `stackTopAt` против `matAt` при сжатии | **Уже исправлено 26.08.** Функция `cutSpan`: одно определение формы среза для `matAt`, `coreMaterial` и `heightAt`. Раньше форму задавали две независимые формулы, и они расходились |

Оптимизации 2.1–2.5 из этого ревью совпадают с тем, что предложили предыдущие
четыре, и сведены в `docs/archive/review-validation.md`. Порядок принят прежний:
**сначала инварианты, потом профилирование** — оптимизировать код, который
считает неверно, смысла нет.

## Что нужно решить, прежде чем начинать

1. **Маски против патчей — это смена ядра, а не добавка.** `patchSRange`,
   `matAt`, `heightAt`, `restack`, `computeCore` и ключ кэша переписываются все.
   Режим «Пазл» (`similarity`) тоже: сравнение по карте материалов останется,
   но генератор целей `genTarget` умеет только прямоугольники.
2. **Совместимость альбомов.** Ссылки на рецепты уже раздавались тестерам;
   рецепт с маской в ссылку не влезет так же просто.
3. **Порядок.** Разумнее сначала карта высот (Этап 3) на существующих
   прямоугольниках — она сама по себе чинит подтверждённые дефекты `restack` и
   `computeCore`, — и только потом маски поверх готовой карты.
