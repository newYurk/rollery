# ADR-001, Erratum 009 — критерий принятия читает одно поле, не два несинхронизированных

- **Статус:** proposed; уточнение шапки и раздела «Критерий принятия» ADR-001.
- **Дата:** 2026-09-04.
- **Заменяет в ADR-001:** шапку документа (строка 3, `- **Статус:** proposed`) и раздел
  «Критерий принятия» (строка 130).
- **Отвечает на находку ревью:** пропущенный класс «Критерий принятия ADR-001 не привязан
  ни к какому механизму» (major, `docs/handoff/core-v2-validation-findings.md`).
- **Кому:** ревьюеру / разработчику Core V2 и владельцу.

## Проблема

ADR-001:130 — «Этот ADR станет `accepted` только после того, как ты подтвердишь область V2 и
список сознательных не-целей» — не привязан ни к полю, ни к артефакту, ни к событию. Все шесть
документов несут «Статус: proposed» бессрочно; ничто не говорит, куда попадает подтверждение
владельца, когда оно случится.

Первая версия этой правки чуть не ввела ту же проблему заново другим способом: добавляла
новое поле «Принято владельцем: <дата>» рядом с уже существующим «Статус: proposed», не
говоря, какое из двух авторитетно. Владелец вписывает дату в новое поле, не трогая старую
строку «Статус:» (инструкция её трогать не просит) — документ показывает одновременно
`Статус: proposed` и `Принято владельцем: 2026-09-10` в одной шапке. Тот же класс
неоднозначности, размноженный на два поля вместо одного.

## Решение — одно авторитетное поле

**Правка шапки ADR-001** (после строки 3, `- **Статус:** proposed`):

```diff
  - **Статус:** proposed
+ - **Принято владельцем:** _(пусто — впишет владелец одной строкой, например «2026-09-10»)_
  - **Дата:** 2026-09-03
```

**Правка раздела «Критерий принятия»** (было → стало):

```diff
- Этот ADR станет `accepted` только после того, как ты подтвердишь область V2 и список
- сознательных не-целей. Реализация Core V2 не считается начатой до появления fixtures
- из этого документа.
+ Этот ADR считается `accepted` тогда и только тогда, когда поле «Принято владельцем»
+ в шапке документа не пусто. Строка «Статус:» выше в шапке — не источник истины, и её
+ не обязательно держать синхронной: она не проверяется программно и не читается ни
+ fixtures, ни этим документом при определении «принят ли ADR» — единственное, что
+ читается, это «Принято владельцем». Если после появления даты кто-то заодно обновит
+ строку «Статус:» на `accepted` для удобства чтения — это чисто косметическая правка,
+ а не обязательное условие.
+
+ Пока поле «Принято владельцем» пусто, ADR фактически `proposed`, и это **не блокирует
+ старт реализации**: реализация Core V2 начинается с fixtures, а они уже зафиксированы
+ в `core-v2-fixtures.md` (это факт контракта, а не решение — сам ADR-001 говорит:
+ «Реализация Core V2 не считается начатой до появления fixtures из этого документа»,
+ а не «до accepted»).
```

## Что это закрывает

Устраняет свободный, ничем не проверяемый критерий «ты подтвердишь» — заменяет его на
конкретное поле, которое можно грепнуть, и явно называет единственный источник истины,
когда полей стало два. Не блокирует уже идущую реализацию первого PR: критерий старта был
и остаётся привязан к существованию fixtures, а не к статусу ADR.
