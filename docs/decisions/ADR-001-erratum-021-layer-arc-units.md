# ADR-001 — Erratum 021: независимый интеграл дуги слоя — в мм, не в единицах каталога

- **Дата:** 2026-09-04
- **Статус:** proposed; точечная правка накопленного текста инварианта 1 и строки F01 «Дуга
  по слоям (независимо)» **до** передачи `core-v2-developer-brief.md` разработчику.
- **Уточняет (поверх `ADR-001-erratum-020-cross-erratum-seams.md`, Патч 3а и Патч 3б):**
  единицы `r` / `ds` в цитируемом `geometry.js`. Не меняет выбор средней линии (рис vs нори)
  и не меняет разрешение `rice.arcMm ≠ nori.arcMm`.
- **Источник:** четвёртый независимый проход по накопленному 001–020 против кода, issue
  [#171](https://github.com/newYurk/rollery/issues/171). Журнал: `docs/handoff/core-v2-validation-findings.md`,
  раздел «Четвёртый прогон».
- **Связанные документы:** `ADR-001-erratum-013-sheet-parameter-vs-layer-arc.md`,
  `ADR-001-erratum-014-core-box-units.md`,
  `ADR-001-erratum-020-cross-erratum-seams.md`, `core-v2-fixtures.md`,
  `play/model/geometry.js`, `play/model/catalog.js`.

## Проблема

Erratum 013/020 предписывают считать независимый интеграл дуги слоя тем же способом, каким
`geometry.js` уже считает длину листа при закрытии кольца, и дают copy-paste:

`const ds = Math.sqrt(r*r + dr*dr) * DPHI`

с `r = top[b] - W/2` (нори, `:1355`) и `r = (r0b + rр)/2` (рис, `:1294-1295`).

В `geometry.js` все эти идентификаторы — **единицы каталога**, не миллиметры.
`const U_MM = 5` (`catalog.js:205`). Длина листа хосомаки там `g.L = sheetCm × 10 / U_MM = 21`
(не 105). Цикл `:1351-1361` складывает `ds` и сравнивает с этим `L` — внутри файла это
согласовано. `arcMm` и вся приёмка F01 снаружи — миллиметры (developer-brief: «внутри V2 все
расстояния — мм»; erratum-013 сам называет «настоящую дугу» 55,37 мм и 90,12 мм).

Erratum 014 уже потребовал ×`U_MM` для `r0(φ)` / `innerBoundaryByRay` из того же файла.
013/020 для тех же `r0b` / `top[b]` этого не сказали.

Численно, F01, пустой хосомаки, упрощение «толщина риса постоянна и равна `T = 1,4`»
(без профиля — только чтобы показать порядок, не как заморозка числа): оракул, скопировавший
цикл нори `:1351-1358` как есть, даёт Σds ≈ 18,12 единиц. Тот же интеграл в мм —
×`U_MM` ≈ 90,6 мм, тот же порядок, что «90,12 мм» первого прогона (разница — профиль
толщины, которого в упрощении нет). Разница единиц ≈ 72 мм ≫ любого `EPS_LENGTH_MM`.

Два исхода, оба плохие:

1. Kernel честно пишет дугу в мм, оракул F01 скопировал `ds` без ×`U_MM` — строка «Дуга по
   слоям» красная на верной реализации.
2. Kernel скопировал тот же цикл в `arcMm`, оракул тоже — оба в единицах, строка зелёная;
   `coveredLengthMm = 105` тоже зелёная (считается из `u`, в мм). Пятикратная ошибка масштаба
   на величине, ради которой строка заводилась, молча проходит. Это tautology «сосед с
   соседом», которую erratum-010 закрывал для u-карты, только теперь через общий copy-paste
   `geometry.js`.

Одна конверсия, не ноль и не две: либо сначала `r_мм = r × U_MM` и тогда Σds уже в мм, либо
Σds в единицах × `U_MM` на выходе. Оба сразу дают ×25.

Это не развилка #134 и не `EPS_AREA_RATIO`. Сторону куска при изгибе erratum не выбирает.

## Патч 1 — инвариант 1 (поверх `erratum-020`, Патч 3а)

Фрагмент про `ds` / разные `r` у риса и нори, который поставил 020, **не трогается** —
механическая склейка «Было»→«Стало» внутри него в 020 уже один раз рвала грамматику, и этот
erratum в ту же ловушку не лезет. Единицы дописываются отдельным предложением туда же, куда
020 уже дописывал предложение про нори-only цикл: после «это следствие геометрии, не брак.»
и перед «Отчёт, где единственное измерение длины…».

Было (накопленное: предложение, которое добавил 020, Патч 3а, «в конец того же абзаца»):

```markdown
Цитируемый код `geometry.js:1351-1358` сам по себе строит только нори; повторное использование его `r`-расчёта для риса без замены на `(r0b+rр)/2` даёт один радиус на оба слоя (Erratum 020) — это не реализация данного инварианта, а ровно тот регресс, который таблица F01 обязана ловить.
```

Стало (предложение 020 сохраняется дословно; после него, перед «Отчёт…», два новых):

```markdown
Цитируемый код `geometry.js:1351-1358` сам по себе строит только нори; повторное использование его `r`-расчёта для риса без замены на `(r0b+rр)/2` даёт один радиус на оба слоя (Erratum 020) — это не реализация данного инварианта, а ровно тот регресс, который таблица F01 обязана ловить. `r`, `W`, `r0b`, `rр`, `top[b]` в этом коде — единицы каталога (`U_MM = 5`, `catalog.js:205`); `ds` поэтому тоже. Независимый интеграл для сравнения с `arcMm` — Σ`ds` × `U_MM` (либо сначала `r_мм = r × U_MM`, тогда Σ`ds` уже в мм; не оба умножения). Copy-paste `ds` в `arcMm` без ×`U_MM` — отдельный регресс единиц, тот же класс, что Erratum 014 закрыл для `innerBoundaryByRay`; F01 ловит его строкой «Дуга по слоям», если оракул сам в мм (Erratum 021).
```

## Патч 2 — приёмка F01, строка «Дуга по слоям (независимо)» (поверх `erratum-020`, Патч 3б)

Было (накопленное состояние — 020, Патч 3б, «Стало»):

```markdown
| Дуга по слоям (независимо) | Для каждого `layerId` в `arcByLayerMm` (минимум `rice` и `nori`) отдельно: `\|arcMm − независимо интегрированная геометрическая дуга на [u0Mm, u1Mm]\| ≤ EPS_LENGTH_MM`, интеграл — по средней линии СВОЕГО слоя (нори: `r = top[b] − W/2`, `geometry.js:1351-1358,1320`; рис: `r = (r0b+rр)/2`, `geometry.js:1294-1295`; формула `ds` общая, Erratum 020). Совпадение `coveredLengthMm` НЕ заменяет эту построчную проверку — обе обязаны проходить одновременно. Значения `arcMm` у `rice` и `nori` на одном и том же `[u0Mm, u1Mm]` **закономерно разные** (разные радиусы при концентрической намотке, Erratum 013) — эта строка не сравнивает их друг с другом, и реализация не обязана и не должна их выравнивать |
```

Стало:

```markdown
| Дуга по слоям (независимо) | Для каждого `layerId` в `arcByLayerMm` (минимум `rice` и `nori`) отдельно: `\|arcMm − независимо интегрированная геометрическая дуга на [u0Mm, u1Mm]\| ≤ EPS_LENGTH_MM`, интеграл — по средней линии СВОЕГО слоя (нори: `r = top[b] − W/2`, `geometry.js:1351-1358,1320`; рис: `r = (r0b+rр)/2`, `geometry.js:1294-1295`; формула `ds` общая, Erratum 020). `r`/`W`/`r0b`/`rр`/`top[b]` в цитируемом коде — единицы каталога; независимый интеграл в мм = Σ`ds` × `U_MM` (либо `r` сначала в мм — не оба), Erratum 021. Совпадение `coveredLengthMm` НЕ заменяет эту построчную проверку — обе обязаны проходить одновременно. Значения `arcMm` у `rice` и `nori` на одном и том же `[u0Mm, u1Mm]` **закономерно разные** (разные радиусы при концентрической намотке, Erratum 013) — эта строка не сравнивает их друг с другом, и реализация не обязана и не должна их выравнивать |
```

## Mutation tests

Добавить в `core-v2-fixtures.md`, раздел «Mutation tests» (после строки 020 про общий радиус
нори на оба слоя):

```markdown
| Записать в `arcMm` слоя сумму `ds` из `geometry.js` без ×`U_MM` (единицы каталога, подписанные как мм) | F01: «Дуга по слоям (независимо)» — оракул в мм (Σ`ds` × `U_MM`) не совпадёт с числом в единицах; расхождение порядка ×5, не шум `EPS_LENGTH_MM` |
```

Мутация безусловна: оракул этой строки после Патча 2 сам в мм, поэтому одинаковая ошибка
«забыли ×`U_MM`» на обеих сторонах больше не проходит. Это ровно тот улов, которого не было
у «Ядро по лучам» в Erratum 014 (там одна константа не ловит одновременно симметричный
регресс и недомноженный отчёт — см. «Предупреждение» 014/020). Здесь ловит, потому что
сравниваются два независимых числа одной размерности, а не `max−min` с порогом.

## Не трогаю

`EPS_AREA_RATIO` (Erratum 006, Слой 5, вопрос 10) и #109 — та же граница, что во всех
предыдущих erratum этого разбора. Развилка #134/#165 — конверсия единиц не выбирает, тянется
ли кусок вместе с листом. Минорные из Слоя 6 (`baseId:'hosomaki'` vs `hoso`; поля F02
`placement`/`vMm`/`lengthMm`; `patch_rotated`) этим листом не закрываются.
