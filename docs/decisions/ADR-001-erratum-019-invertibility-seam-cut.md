## Проблема

Erratum 005 закрыл `seam-neighbourhood-free-parameter`: доля двухслойных лучей **нори**
равна `overlapArcRad / 2π ± EPS_RAY_FRACTION`, окрестность шва имеет имя и число.
На F01 `overlapArcRad / 2π ≈ 0,19`. `wrapIntersectionsByRay` в этой строке — счётчик
слоёв нори (1 или 2), не всех слоёв подряд.

Erratum 010 добавил строку приёмки F01 «Обратимость по лучам»:

> `sheetMap.uAtRayMm` строго монотонна по `rays.angleRad` вне явно выделенной угловой
> окрестности шва

Без имени и формулы. Та же фраза стоит в инварианте 3 (`ADR-001-erratum-010-report-completeness.md:311`)
и в mutation test (`:286`). Свободный параметр, который 005 убрал у «Нори по лучу»,
вернулся на новую строку приёмки.

**Минимальный контрпример.** Реализация исключает из проверки монотонности все лучи с
`wrapIntersectionsByRay = 2`. Это ~19 % сетки на F01. Оставшаяся дуга выглядит монотонной
даже если отображение `θ → u` в зоне нахлёста — мусор. F01 зелёный. Исключение в 1 бин
и исключение в 19 % лучей — разные проверки; формулировка их не различает.

Дополнительно: `sheetMap.uAtRayMm` и `turnIndexAtRay` — по одному числу на луч, а в зоне
нахлёста у луча два пересечения листа (кольцо и хвост). Какое `u` писать — не сказано.
От этого выбора зависит, где вообще живёт разрыв монотонности.

## Правило выбора при двух пересечениях

На луче с нори-`wrapIntersectionsByRay[i] = 2` (счётчик erratum-005) поля
`sheetMap.uAtRayMm[i]` и `sheetMap.turnIndexAtRay[i]` описывают **внутреннее**
пересечение: меньший `turnIndex`, ближе к ядру (меньший радиус). Хвост нахлёста на этом
луче в `uAtRayMm` не пишется — его зона уже поймана строкой erratum-005 и полями `seam.*`.
На F01 (кольцевая намотка, не спираль: `winding: 'spiral'` только у `uzumaki`,
`catalog.js:183`) два значения sheet-`u` на луче — это ровно те же лучи, что несут два
слоя нори.

Следствие для внутреннего `u(θ)`: это пила с **одним** скачком — разрыв непрерывности
внутреннего `u` при обходе окружности. Это не сектор ширины `overlapArcRad`. На
кольцевом F01 внутреннее `u` покрывает грядку риса, не весь лист: голые полосы обеих
кромок уходят в хвост нахлёста (`geometry.js:1127-1130` «голые полосы с обоих концов
уходят в нахлёст, а не в кольцо»; `s = sRice0 + Lrice · (b / NB)` на `:1272`;
`Lbare = (L − sRice1) + sRice0` на `:1378`). Ориентир масштаба, не oracle V2: на входе
F01 `sRice0 ≈ 5,04 мм`, `sRice1 ≈ 92,4 мм`, внутреннее `u` скачет `sRice1 → sRice0`,
**не** `L → 0`. `u = 0` на этом угле — ближняя голая кромка, то есть **внешнее**
пересечение, которое эта же правка запрещает писать в `uAtRayMm`. Искать скачок как
`uAtRayMm ≈ 0` на F01 — нарушить собственное правило внутреннего пересечения.

`fromULength` эту строку F01 не уточняет: F01 несёт `fromUZero`, переворот — зона F08.
Направление монотонности следует `windDirection`; место скачка — разрыв внутреннего
`u`, без литерала `u = L`.

## Как проверять монотонность

Сетка сортируется по возрастанию `rays.angleRad`. Проверяется каждая пара соседних
лучей **и** круговая пара `(последний, первый)`. Из проверки исключается не больше
одной пары — та, что пересекает разрыв внутреннего `u`. Не «индекс 0 массива» и не
«склейка `0 ≡ 2π` параметризации»: круговая пара входит в проверку всегда, и она же
оказывается исключённой, если kernel положил разрыв внутреннего `u` на эту склейку
(легаси кольца так и делает: нахлёст «ложится от угла 0», `geometry.js:1375`). Если
положил в другое место — исключается та пара, где внутреннее `u` скачет, а круговая
пара остаётся в проверке.

`maxRoundTripErrMm` — ошибка round-trip **сохранённых** значений `uAtRayMm` (внутренних)
на том же луче. Хвостовое `u` через `sheetMap` обращаться не обязано: для него нет
записи в `uAtRayMm`, его зона — erratum-005 / `seam.*`. Харнесс, который гоняет через
`θ → uAtRayMm` все `u` листа включая хвост, получит `|u_хвост − u_внутр| ~ Lrice` и
окрасит верный kernel — это не проверка 010.

## Патч 3 — комментарии полей `sheetMap` (поверх Патч 2 erratum-010)

Было:

```ts
    uAtRayMm: number[]        // прямая выборка: u, отображаемый на данный луч
    turnIndexAtRay: number[]  // номер витка на этом луче (для futomaki с несколькими оборотами)
```

Стало:

```ts
    uAtRayMm: number[]        // u внутреннего пересечения на этом луче (меньший turnIndex / меньший радиус). При нори-wrapIntersections=2 хвост нахлёста сюда не пишется
    turnIndexAtRay: number[]  // номер витка того же внутреннего пересечения (для futomaki с несколькими оборотами)
```

Форма типа не меняется — только правило, какого из двух пересечений эти числа.

## Почему исключение — не `overlapArcRad`

`overlapArcRad` — правильное имя для доли двухслойных лучей нори (erratum-005). Для
обратимости `θ → u` внутреннего витка эта зона — обычная часть окружности: внутреннее
`u` там — начало грядки риса и остаётся в той же монотонной ветке. Подставить
`overlapArcRad` как исключение монотонности = вычеркнуть 19 % сетки из инварианта 3,
что и есть контрпример ревьюера. Разрыв — одна пара лучей на скачке внутреннего `u`,
не сектор нахлёста.
