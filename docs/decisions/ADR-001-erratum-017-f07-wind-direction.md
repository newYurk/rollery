# ADR-001 — Erratum 017: `windDirection` во «Вход» F07

- **Дата:** 2026-09-04
- **Статус:** proposed; правка исполняемого входа F07. Не блокирует PR1 (F07 вне скоупа
  первого PR), закрывает тот же класс отката, который erratum-008 уже чинил у F01–F05.
- **Дополняет (поверх `ADR-001-erratum-007-ordinal-vs-coordinate.md`, раздел «Вход» F07):**
  обязательное поле `windDirection: 'fromUZero'`. Исторический список «явно патченных
  входов» внутри текста Erratum 008 не переписывается (два источника истины хуже одной
  дыры, закрытой поздним номером).
- **Источник:** независимый ревьюер-человек, issue [#171](https://github.com/newYurk/rollery/issues/171),
  пункт 5 (major). Проверено независимо: `docs/handoff/core-v2-validation-findings.md`,
  Слой 6.
- **Связанные документы:** `ADR-001-erratum-007-ordinal-vs-coordinate.md`,
  `ADR-001-erratum-008-wind-direction.md`, `core-v2-fixtures.md`.

## Проблема

Erratum 008 сделал `RecipeV2.windDirection` обязательным: отсутствующее или чужое значение
→ `invalid: recipe_missing_wind_direction` до любой намотки. Чтобы существующие fixtures
не противоречили сами себе (`status: valid` и одновременно `invalid` по новому правилу),
008 явно дописал поле во «Вход» F01, F02, F03, F04a, F04b, F05
(`ADR-001-erratum-008-wind-direction.md:102-128`).

F07 в этот список не вошёл. Проза 008 (`:80`) уже требует `fromUZero` «для F01–F08 …
кроме специально предназначенного для проверки переворота F08» — но исполняемый «Вход»
F07 (`ADR-001-erratum-007-ordinal-vs-coordinate.md:49-57`) поля не содержит. Есть только
`Рука: neutralHand`.

Это ровно тот класс отката, который 008 чинил у F01–F05: правило «поле обязательно»
живёт в ADR, а нормативный сценарий fixture его не несёт. Разработчик, собравший девять
рецептов F07 буквально по входу, получает `invalid: recipe_missing_wind_direction` на
каждом шаге; приёмка F07 требует `valid` на всех девяти и обоих порядках массива.

F06 сам по себе входа-рецепта не имеет — он репрогоняет F01–F05, F07, F08. Пока F07 без
поля, F06 транзитивно красный на тех же девяти шагах. Отдельной правки входа F06 нет.

## Патч 1 — `ADR-001-erratum-007-ordinal-vs-coordinate.md`, раздел F07 «Вход»

Было (накопленное состояние — текст Erratum 007, поле `windDirection` ни одним более
поздним erratum во вход F07 не добавлялось):

```markdown
- База: `futomaki` (как в F05 — нужен запас по `placementWindowMm` (`nearEdgeMm`/`farEdgeMm`) по обе стороны от 60 мм).
- Патч-сосед `cucumber`, **неподвижный**: `uMm = 60`, `vMm = sheet.widthMm / 2`, `placement: 'embedded'`. `widthMm`/`heightMm` — из каталога, фиксируются численно после первого принятого запуска (как в F02).
- Патч-зонд `tamago`, **разный `materialId`**, `placement: 'embedded'`, тот же `vMm = sheet.widthMm / 2`. Заведомо тонкий: `widthMm` того же порядка или меньше, чем у соседа (фиксируется после первого запуска вместе с соседом), чтобы даже полное совпадение центров давало маленькое окно перекрытия, а не тест на объёмную коллизию.
- Серия из **девяти** рецептов, отличающихся только `uMm` зонда: `56, 57, 58, …, 64` мм — шаг 1 мм, ровно проходит через `uMm` соседа (60).
- Для каждого шага прогоняется пара рецептов с патчами в порядке `[cucumber, зонд]` и `[зонд, cucumber]`.
- Дополнительно один парный рецепт с **обменёнными** `uMm`: `uMm(cucumber) = 56`, `uMm(зонд) = 60`. Значение 56 — это первый шаг уже прогнанной девятки (не новое число), поэтому результат обменянного рецепта можно сверить напрямую с уже посчитанным шагом `uMm(зонд) = 56` без дополнительных прогонов. Не путать с перестановкой массива (F05) — здесь переставлены сами числа между двумя разными патчами, а не порядок элементов `patches`.
- Рука: `neutralHand`.
```

Стало (добавлена одна строка, константа по всей серии — тот же приём, что у F03/F05 в
erratum-008: ось F07 — координата против порядкового номера, не направление намотки):

```markdown
- База: `futomaki` (как в F05 — нужен запас по `placementWindowMm` (`nearEdgeMm`/`farEdgeMm`) по обе стороны от 60 мм).
- Патч-сосед `cucumber`, **неподвижный**: `uMm = 60`, `vMm = sheet.widthMm / 2`, `placement: 'embedded'`. `widthMm`/`heightMm` — из каталога, фиксируются численно после первого принятого запуска (как в F02).
- Патч-зонд `tamago`, **разный `materialId`**, `placement: 'embedded'`, тот же `vMm = sheet.widthMm / 2`. Заведомо тонкий: `widthMm` того же порядка или меньше, чем у соседа (фиксируется после первого запуска вместе с соседом), чтобы даже полное совпадение центров давало маленькое окно перекрытия, а не тест на объёмную коллизию.
- Серия из **девяти** рецептов, отличающихся только `uMm` зонда: `56, 57, 58, …, 64` мм — шаг 1 мм, ровно проходит через `uMm` соседа (60).
- Для каждого шага прогоняется пара рецептов с патчами в порядке `[cucumber, зонд]` и `[зонд, cucumber]`.
- Дополнительно один парный рецепт с **обменёнными** `uMm`: `uMm(cucumber) = 56`, `uMm(зонд) = 60`. Значение 56 — это первый шаг уже прогнанной девятки (не новое число), поэтому результат обменянного рецепта можно сверить напрямую с уже посчитанным шагом `uMm(зонд) = 56` без дополнительных прогонов. Не путать с перестановкой массива (F05) — здесь переставлены сами числа между двумя разными патчами, а не порядок элементов `patches`.
- `windDirection: 'fromUZero'` — константа на всех девяти шагах, обоих порядках массива и обменянном рецепте. Менять поле вместе с `uMm` или порядком `patches` нельзя: F07 проверяет координату против порядкового номера, и любой разброс `windDirection` внутри серии смешает две оси в одном прогоне (та же ошибка, которую erratum-008 уже запретил для F03 и F05). Значение — то же, что у F01–F05; F08 отдельно проверяет переворот.
- Рука: `neutralHand`.
```

Нормативный вход F07 — Патч 1. Список «явно патченных входов» внутри текста Erratum 008
этим erratum не переписывается: править исторический файл 008 задним числом дало бы два
источника истины. Читатель идёт по номеру: 008 не дошёл до F07, 017 дописывает вход.
