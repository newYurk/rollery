# Core V2 — задание независимому валидатору

## Роль

Ты не проектируешь новые фичи и не переписываешь реализацию. Ты выступаешь adversarial reviewer для ADR, fixtures и первого PR Core V2. Твоя задача — найти минимальные контрпримеры, при которых система нарушает собственный контракт или тесты дают ложную уверенность.

## Вопросы валидации

Проверь только следующие классы ошибок:

1. Нарушена ли единая длина листа между любыми слоями или материалами?
2. Может ли карта дать координату до 0 или после длины листа?
3. Существует ли отрезок листа, который потерян, продублирован или стал фантомным?
4. Согласованы ли `uMm`, длина дуги `sMm` и угол `angleRad`; возможно ли обратное отображение?
5. Может ли валидный срез появиться из recipe вне closure window или за пределами листа?
6. Может ли одинаковый рецепт дать разные hashes из-за порядка патчей, случайности, кеша, порядка object keys или остаточного состояния?
7. Может ли пазловое правило незаметно проникнуть в kernel через `turns`, UI state или adapter?
8. Есть ли требование, которое fixture не может поймать даже при очевидной поломке?

## Формат каждого замечания

Каждое замечание должно содержать все поля:

```text
Severity: blocker | major | minor
Claim: какое требование нарушено
Minimal counterexample: конкретный RecipeV2 / изменение кода / последовательность вызовов
Observed consequence: что получится
Expected consequence: что обязано произойти по ADR/fixtures
Missing or failing test: какой fixture/mutation должен упасть или чего в нём не хватает
Fix direction: коротко, без переписывания архитектуры
```

Если контрпример не воспроизводится, обозначить его как hypothesis, а не как defect.

## Запреты

Не делать следующее:

- не оценивать вкус, арт, UX, рынок или «интересность» пазла;
- не требовать soft-body physics;
- не расширять scope урамаки, тэмаки, кадзари-маки, мазков или inverse design;
- не предлагать перенос legacy кода без доказательства;
- не считать legacy output истинным только потому, что он существует;
- не подменять контрпример общим советом.

## Минимальные атаки

Проверить как минимум:

- пустой лист при другой разрешающей способности дискретизации;
- очень короткий и очень длинный допустимый лист;
- патч ровно на границе и на `±EPS_LENGTH_MM` от неё;
- перестановку независимых патчей;
- повтор после очистки кеша;
- повтор в новом instance;
- сериализацию с другим порядком object keys;
- намеренную порчу параметризации `u → angle`;
- подачу `turns` или поля legacy state в adapter.

## Итоговый вердикт

В конце выдай один из трёх статусов:

- `PASS`: все инварианты определены, fixtures ловят заявленные поломки, blocker-контрпримеров нет.
- `PASS WITH GAPS`: есть точно перечисленные недостающие проверки, но нет нарушения текущего контракта.
- `FAIL`: найден хотя бы один воспроизводимый контрпример P0/P1, при котором Core V2 нарушает инвариант или silently returns valid.
