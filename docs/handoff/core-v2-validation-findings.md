## Вердикт

**`FAIL`**

FAIL, не PASS WITH GAPS. Задание валидатору само задаёт планку: «FAIL: найден хотя бы один воспроизводимый контрпример P0/P1, при котором Core V2 нарушает инвариант или silently returns valid» (adversarial-validation-brief.md:75), а задание оркестратора уточняет: «контракт, который нельзя реализовать как написано, потому что несущий термин не определён, — это FAIL, а не gap». Эту планку независимо друг от друга перекрывают минимум четыре из десяти переданных survivors:

(1) closure-window-undefined — несущий термин пяти нормативных мест (инвариант 5, F02, F03, F04 ADR-001 и fixtures.md) не имеет числа нигде в репозитории, кроме самих шести контрактных документов — проверено grep'ом по всему дереву (`grep -rniE "closure.?window|зона смыкани"`). Без него нельзя составить даже F02 — единственный fixture PR1 с ингредиентом.

(2) covered-length-is-a-tautology — приёмка F01 (единственного fixture, который «нельзя спрятать ошибку длины под влиянием начинки», fixtures.md:69) по построению не может покраснеть на дефекте #165, ради которого затеян весь Core V2, потому что coveredLengthMm/uncoveredLengthMm/phantomLengthMm выводятся из той же карты u, которую они якобы проверяют. Проверено численно: наивная реализация bin-пропорции (буквально как в legacy) даёт на F01 (пустой хосомаки, 105 мм) 87,36 мм суммы u-интервалов и в слое риса, и в слое нори — при настоящей дуге 55,37 и 90,12 мм соответственно — и всё равно возвращает coveredLengthMm = 105,00 ровно.

(3) no-area-invariant-variant-b-passes — это не гипотетический контрпример, а уже случившийся факт истории проекта: «вариант B» построен, замерен и отвергнут 03.09.2026 07:56 (STATE.md:44-49) именно потому, что портит площадь куска (1,14 → 1,20) и даёт некруглость хосомаки 59-68% при потолке 30 — и та же самая реализация проходит F01-F06 целиком, поскольку единственная проверка площади во всём контракте — «areaMm2 > 0 и стабильна между повторными запусками» (fixtures.md:104).

(4) no-fixture-catches-ordinal-134 — измеренная 03.09 причина #134 (действует порядковый номер укладки, а не координата u; кусок едет 34 мм без отклика на срезе, затем прыгает на 15 мм при смене соседа) не ловится ни F03 (одиночный патч всегда идёт в ядро), ни F05 (legacy уже сортирует по u, так что перестановка массива — no-op и на дефектной, и на исправленной реализации).

Дополнительно шесть других переданных blocker-findings (invariant-3-unmeasurable, seam-neighbourhood-free-parameter [закрыто erratum-005], hash-domain-undefined, canonical-serialization-undefined, box-core-absent-from-pipeline, f04-disjunction-and-tuck-reach [закрыто erratum-004]) и минимум восемь классов дефекта, которые все восемь линз структурно не искали (Часть 1 выше) — включая направление намотки (handedness), которое само по себе достаточно для отдельного FAIL, поскольку ни один из 8 инвариантов ADR его не различает.

Итог: это не «нужно доопределить пороги» (что было бы PASS WITH GAPS). Контракт в нынешнем виде: (а) содержит несущий термин без числа, блокирующий составление единственного ingredient-fixture PR1; (б) сертифицирует уже отвергнутую замером реализацию как образцовую; (в) не видит измеренную причину собственного существования (#134) ни в одном из шести fixtures. Любого из пунктов (а)-(в) по отдельности достаточно для FAIL по формулировке задания; втроём и с учётом Части 1 вердикт однозначен.

### Три блокера — по приоритету

1. Дать closure window определение числом или формулой с явным источником (или убрать термин из инварианта 5 и из F02–F04) — без этого нельзя составить даже единственный ingredient-fixture PR1 (F02), и первый PR блокирован не сложностью реализации, а отсутствием входа.
2. Владельцу самой решить зарезервированную за ней развилку «растягивается ли кусок начинки вместе с изгибающимся листом» (STATE.md) и внести в ADR-001 инвариант сохранения площади/вещества постели рядом с инвариантом длины листа, с явным допуском и указанием, какое ограничение уступает — иначе уже построенный и отвергнутый по замеру 03.09 вариант B пройдёт весь набор F01–F06 как образцовая реализация.
3. Пересчитать приёмку F01 через независимый интеграл дуги по каждому слою (а не через ту же карту u, которую она обязана проверять) и добавить fixture на измеренную 03.09 причину #134 (действует порядковый номер укладки, а не координата uMm) — иначе приёмка не ловит ни одну из двух причин, ради которых Core V2 вообще затевается.
