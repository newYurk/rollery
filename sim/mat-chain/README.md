Пятая попытка кинематики (после `../kin-grab`, `../kin-mat`, `../reference`, `../spiral-*`), переписанная
под **главную поправку** `../KINEMATICS.md` от 26.08.2026, 12:50: циновка — не жёсткая дуга сверху, а

## 1. Как устроена циновка

### Цепочка

Циновка — полилиния из `n_mat` узлов с шагом `ds = MAT_DS = 0.25 T`, длиной
`L_mat = 1.25 · L_sheet = 48.4 T` (настоящая макису 24 см против листа нори 19–21 см). Лежит **под
листом** с нулевого кадра: `y = MAT_Y0 = −0.06`, ближний край в `x = 0` совпадает с ближним краем нори.

Каждый шаг цепочки (раз в `CHAIN_EVERY = 2` подшага MPM) — предсказание скоростей и затем проекция
ограничений методом Гаусса–Зейделя, `MAT_ITERS = 8` проходов вперёд-назад (один проход вперёд доносит
движение пальцев до противоположного конца, поэтому восьми хватает):

```
нерастяжимость:      |p[i+1] − p[i]| = ds
минимальный радиус:  |p[i+1] − p[i−1]| ≥ 2·ds·cos( ds / (2·R_bend) )   = 0.4845 T
                     при R_bend = MAT_RBEND = 0.5 T (ширина бамбуковой палочки ≈ 2–3 мм при T ≈ 5 мм)
пол стола:           p[i].y ≥ MAT_Y0
```

Ограничение на хорду через два сегмента — это ровно «угол излома не больше `ds/R_bend`». Складка мельче
0.5 T невозможна **по построению**: проекция её просто не пропускает, никакой изгибной жёсткости
подбирать не надо.

### Контакт через сетку

Один подшаг — семь ядер вместо одного:

```
p2g → grid_pre → mat_gather → mat_apply → grid_post → mat_react → g2p
```

* `mat_gather` — параллельно по **сегментам** цепочки: сегмент задевает 4×4 клетки, поэтому это дёшево.
  На узлы сетки в полосе `band = 1.05·dx` рассыпаются скорость циновки и её нормаль (нормаль сегмента —
  `n = rot(t, +90°)`, то есть всегда со стороны еды, потому что циновка не выворачивается).
* `mat_apply` — по узлам сетки, один контакт на узел против усреднённого репера:
  * ближе `stick = 0.6·band` — узел **прилипает** к циновке целиком (`v = v_mat`). Это мокрый рис,
    которым нори приклеена к макису. Без прилипания раздельный контакт может тащить только то, что на
    него давит, а при `GRAVITY = 0.01` не давит ничто — и циновка просто выскальзывает из-под листа
    (проверено: без прилипания нори остаётся лежать на столе, а циновка уезжает вперёд одна);
  * дальше — обычный раздельный контакт Кулона, `MU_MAT = 2.2`, срабатывает только при `v_rel·n < 0`.
* `mat_react` — обратный проход по тем же сегментам: импульс, который циновка потратила на еду,
  собирается обратно на её узлы. Это и есть та реакция, которую меряет сервопривод давления.

### Сервопривод: форма — следствие контакта

Реакция на узле фильтруется по времени (`τ = TAU_F = 0.5`) и сглаживается вдоль цепочки по 5 узлам,
после чего узел движется по радиусу оси намотки:

```
f_target = P · ds
err      = (f_i − f_target) / f_target
v_n      = −V_RADIAL · clamp(err, −1, 1)                    (давление: не давит — идём внутрь)
           − V_RADIAL · CIRC_W · clamp( (R − r_i)/(0.35·R), −1, 1 )   (возврат на круг контроллера)
```

Второе слагаемое обязательно: узел, который ни к чему не прикасается (над щелью между начинками или
пока первый оборот ещё не набрал постель), иначе уходит внутрь навсегда и намотка схлопывается.

### Ось намотки — из сохранения площади

Ось — точка `C = (x_c, R)` над точкой отрыва циновки от стола, `R` ведёт **силовой контроллер**
(тот же, что в `../reference`), но зажатый бухгалтерией площадей:

```
A(x_c) = площадь всего, что уже поднято  (сумма объёмов частиц с начальным x < x_c)
R_area = √( A(x_c) / π )
R ∈ [ R_TIGHT · R_area , R_LOOSE · R_area ],   R_TIGHT = 1.11, R_LOOSE = 1.35
Ṙ = V_R_GLOBAL · clamp( (F − P·arc) / (P·arc), −1, 1 )
```

`R_TIGHT` — важнее, чем кажется: площадная формула считает ролл без единого пузырька, а намотанный
ролл всегда с воздухом. При `R_TIGHT = 1.0` геометрическая цель сама давит ролл до `J = 0.85`
(сохранение 0.87) независимо от давления.

## 2. Фазы

| Фаза | Что происходит | Чем задаётся |
|---|---|---|
| `lift` | нос петли раскрывается от нуля до `r_nose`, ближний конец циновки едет прямо вверх над ним | `x_e = π·r`, `r: 0 → r_nose` |
| `close` | нос зафиксирован, ближний конец несётся вперёд до дальней линии риса | `x_e: π·r_nose → x_e_end` |
| `hold` | прижим и пауза; форма плавно перетекает из петли в круг (`w_roll: 0 → 1`) | `t_hold = 6 + 2·--hold` |
| `roll` | качение вперёд, задний край циновки выводится из-под ролла | `x_c += v_c·dt` |
| `squeeze` | ничего не едет, давление растёт до `P_press`, обжим по кругу | `|err| < 0.10` или 46 ед. времени |

### Первый оборот — не круг, а петля с плоским низом

Это главный урок этой попытки. Мишень для цепочки задаётся **по длине дуги от точки отрыва** `a`:

```
b1   = x_L − x_n            длина нижней ветви (лежит на столе, НЕ двигается: x = i·ds)
nose = π · r_n              полуокружность носа
a ≤ b1              :  (x_L − a, 0)
a ≤ b1 + nose       :  ψ = (a − b1)/r_n ;  (x_n − r_n·sin ψ, r_n − r_n·cos ψ)
иначе               :  (x_n + (a − b1 − nose), 2·r_n)

x_n = (x_e + π·r_n)/2        положение носа: следует из того, что нижняя ветвь не скользит
r_n = max( R_bend, (h_top + h)/2 · (0.65 + 0.35·--lift) ),   h = T + w = 1.12
x_e_end = max( s_fold, π·r_n + 0.6 )
```

`r_n = (h_top + h)/2` — это ровно тот радиус, при котором рис возвращающейся ветви встречается с рисом
нижней: `2·r_n − h = h_top`. Именно это повар и называет «довести ближнюю линию риса до дальней».

Круг на первом обороте не работает вообще: намотка угла `φ` радиуса `R` вмещает `R²(φ − sin φ)/2`, а
поднято к этому моменту `φ·R·h` — при `φ < 2π` первое меньше второго, и циновка не заворачивает постель,
а бульдозерит её. Отсюда же дуга подъёма: носу радиуса `r` нужно ровно `π·r` завёрнутой циновки, поэтому
на стадии `lift` ближний конец идёт по прямой `x_e = π·r`, длина пути `√(π²+4)·r_nose`.

### Вывод переднего края

Сколько циновки держится на ролле — не константа. Её ведущий конец обязан **проходить над листом,
который ещё лежит впереди**, иначе он ложится на постель и гребёт её (в прогоне это было 11 % риса,
вытолкнутого за край стола). Виток на угле `φ` стоит на высоте `R(1 − cos φ)`, отсюда

```
φ_lead = min( PHI_LEAD , 2π − arccos( 1 − (h_вперёд + 0.35)/R ) )
i_lo   = max( i_lo , i_ct − φ_lead·R/ds )        (узлы ближе i_lo — снятый наружу клапан, неактивны)
```

`h_вперёд` = толщина постели (`T + w`), голого клапана (`w`) или начинки, которая стоит впереди. Когда
лист кончился, `h_вперёд = 0` и намотка смыкается на все 2π — это и есть обжим. Это цепочечный аналог
архимедовой спирали, которой `../reference` решал ту же задачу.

### Пальцы (`--fingers`)

Вторая кинематическая опора на первом обороте: плита сверху над стопкой (`y = h_top − 0.9`, но не ниже
верха постели, плюс 0.35), от `x_n + 0.35` до `s_fold + 0.8`. Гасит вертикальную скорость вверх и на
половину — горизонтальную, плюс отдельный стоп «не выдавливаться вперёд» на переднем краю.

Плита стоит **впереди носа петли**: позади него стопка уже перевернулась и обязана подниматься.
Держали от `x = 0.25` — и раскладка 4 оставляла огурец и тамаго лежать на столе (в ролл они не попадали
вовсе). `--fingers 0` выключает.

## 5. Что не получилось

1. **Складок не ноль.** Цель `../KINEMATICS.md` — строгий ноль. По старому порогу (`|κ| ≥ 1/(T+w) =
   0.89`) в конце остаётся 1 / 6 / 3 смены знака, максимум по прогону 6 / 12 / 11. Амплитуда при этом
   везде 0.18–0.19 T, то есть **меньше требуемых 0.3 T**. Диагностика по раскладке 4 (скрипт в истории,
   не сохранён): развороты сидят двумя кучками — у нижне-правого края ролла, где лист входит в намотку
   через щель `φ_lead…2π`, и наверху, где циновка отпускает ролл. Это места, где нори *должна* где-то
   согнуться, переходя со стола на виток; жёсткого гофра (несколько складок подряд на одной длине волны)
   на кадрах нет ни в одной фазе.
   Поэтому добавлена **вторая метрика — `wrinkles_mat`** с порогом `1/MAT_RBEND = 2.0`: «складка — это
   когда лист согнут туже, чем может согнуться бамбуковая палочка». По ней в конце 0 / 1 / 1. Считаю
   честным сказать: по порогу, который задаёт сама циновка, цель достигнута почти везде, а по старому
   порогу `1/(T+w)` — нет, и старый порог ловит собственную кривизну ролла заодно со складками.
2. **Раскладка 2 теряет половину тамаго.** Одна высокая начинка (2.0 T) у самого края выдавливается
   вперёд из-под петли и остаётся на столе (видно на `out/frames_2/f0027242_squeeze.png`, кусок жёлтого
   при `x ≈ 14`). Пальцы её держат сверху, но не сбоку. `tail_outside 6.7 %` — это она. На раскладке 4,
   где начинок четыре и они подпирают друг друга, такого нет (2.7 %).
3. **Формула оборотов не сходится на 2 и 4** (`Δ = 0.52` и `0.29` при допуске 0.25). Причина считается
   прямо в JSON: `crossings_predicted` считается по номинальному `s_fold`, а фактический подворот
   (`s_fold_actual`) вышел 7.25 и 9.25 вместо 4.9 и 11.2 — петля сама решает, сколько листа съесть.
   Поле `crossings_predicted_actual` пересчитано по фактическому подвороту, но и оно не всегда попадает.
4. **`stable = false` на 1 и 4** — из-за `nori_torn`: максимальный зазор между соседними частицами нори
   0.139 и 0.386 T при пороге `2.5 · шаг частиц = 0.12`. Настоящего разрыва ленты на кадрах нет
   (`nori_components_map` = 1), это растяжение шага в тугой спирали и один отставший кусочек. Порог
   унаследован от `../reference` и для намотанного в 2.5 оборота листа слишком строгий — но менять
   чужую метрику в этой попытке я не стал.
5. **Форма цепочки задаётся мишенью, а не только контактом.** По заданию кинематически должен был
   задаваться только ближний конец. Так не заработало: свободная цепочка с сервоприводом давления не
   сворачивает постель в ролл — она либо схлопывается (не касаясь ничего, узел идёт внутрь вечно), либо
   уезжает вперёд плоской лентой. Пришлось задавать мишень по длине дуги (петля → круг), а свободой
   оставить **радиус** (силовой контроллер + пол/потолок по площади) и локальные отклонения узлов от
   мишени (сервопривод давления). Это шаг назад от формулировки задания и главный кандидат на
   переделку.
6. **Не проверено самопересечение цепочки.** Отталкивания между несоседними узлами нет: при намотке
   меньше 2π и снятом клапане перехлёста не возникает, но на других ручках может.
7. **Квадратный прижим (раскладка 5) не поддержан.** Цепочка обжимает круг; SDF скруглённого квадрата
   из `../reference` не переносился. Раскладка 5 отрабатывает, но форму даёт круглую.

## 6. Запуск

```bash
cd sim/mat-chain
../.venv/bin/python run.py --layout 1 --grid 240 --particles 16000 --frames 12
../.venv/bin/python run.py --layout 4 --fingers 0 --tuck 1.2 --hold 3 --tag _nofing
```

Пишет в `out/`: `metrics_<tag>.json`, `material_<tag>.npy/.png` (карта классов 600×600),
`particles_<tag>.npz` (частицы + узлы циновки в поле `mat`), `final_<tag>.png`, `frames_<tag>/*.png`.

Вариант виден в `../lab` автоматически (папка с `run.py`), ползунки — speed / press / tuck / hold /
lift / fronty.
