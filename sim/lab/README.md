# Лаборатория скрутки

Стенд, чтобы **смотреть, как крутится ролл**, а не разглядывать итоговый скрин.
Питон знать не нужно: всё в браузере. Здесь же — что выбирать и как лаборатория
соотносится с игрой (раньше это лежало отдельным `README-выбор.md`).

```bash
cd ~/Desktop/Home/Projects/rollery/sim/lab
./lab.sh
```

Откроется `http://127.0.0.1:8770`. Остановить — `Ctrl+C` в том же окне.

## Запускать только через `lab.sh`

**Не** `python serve.py`. Лаборатория запускает расчёты **тем же интерпретатором,
которым запущена сама** (`PY = sys.executable`), а Taichi стоит только в
`sim/.venv`. Запустишь системным питоном — сервер поднимется, кнопки будут
нажиматься, и каждый прогон упадёт с кодом 1: выглядит как поломка расчёта, а
сломан запуск. `lab.sh` включает окружение первой же строкой. Если нужно в фоне:
`cd sim/lab && ../.venv/bin/python serve.py`.

## Лаборатория и игра — разные программы

**Они не общий код и никогда им не были.**

| | лаборатория (`sim/`) | игра (`play/index.html`) |
|---|---|---|
| что делает | считает **настоящую физику**: частицы, контакты, MLS-MPM | мотает **спираль** по формуле |
| на чём | Python + Taichi | JavaScript в браузере |
| сколько идёт | минуты на один ролл | **1–8 мс**, укладывается в кадр |
| зачем | ответить, **как оно на самом деле** | показать это игроку за 16 мс |

Порядок работы: в лаборатории прогоняется вопрос → из прогона достаётся
**число** → число едет в игру как формула или константа с пометкой, откуда
взялось → в игре его держит проверка `play/checks.js`. Физика из лаборатории в
игру **не переносится** — только выводы. (Встроенная симуляция в игре — открытый
вопрос #68, но и она будет отдельной программой, а разброс — от руки игрока.)

| вариант | когда брать |
|---|---|
| **★ Эталон (`reference2`)** | **по умолчанию.** Победитель очной ставки 26.08: циновка под листом заворачивается вместе с роллом, пальцы держат начинку |
| Прежний эталон (`reference`) | первая сборка, заменена. Для новых прогонов не брать |
| Спираль · завивка | только для **сладкого рулета** — у него нет подворота |
| Спираль · посев | то же, второй кандидат; что из двух правда — вопрос к прогону (#64) |
| Лопатка | если надо проверить подворот без пальцев на начинке |
| ✗ Захват края | **не брать.** Отвергнут: нори пальцами не берут |
| ✗ Первая версия | **не брать.** Историческая: циновка катится по столу — так не крутят |
| Песочница | личная копия, можно ломать |

Урамаки в лаборатории пока нет (нори внутри, рис снаружи, циновка в плёнке) —
issues #3, #25.

**Раскладки** 1–7: пустой лист, тамаго у края, лосось в середине, четыре
начинки, переполнение с квадратной формой, футомаки с набитым ядром, футомаки
как в жизни — подписи читаются из самой сцены. *(До 29.08 в списке значились
«рулет» и «лаваш» — их там нет ни у одного варианта; спиральные базы считаются
отдельными сценами `spiral-*`.)* **Рука** — ползунки сцены: скорость, прижим, глубина подворота,
удержание, подъём циновки, передний край дуги. **Подробность** — быстро (~10 с),
обычно (~25 с), точно (~60 с).

## Что показывает правая половина

- **Проигрыватель**: скрутка кадр за кадром с подписью фазы — подъём края,
  заведение, подворот, прокатка, замыкание, прижим. Пробел — пауза, стрелки — по кадру.
- **Срез** — то же, что игрок увидит в игре.
- **Что получилось** — числа с подсветкой; канонические пороги живут в
  исполняемой проверке `sim/reference2/checks/` (не здесь). О чём говорят:
  сохранение массы — материал не теряется; сжатие риса J — сжат, но не
  раздавлен; обороты обёртки — намотка плотная, без воздуха (рядом предсказание
  формулы); целость нори; порядок начинок в ядре; складки листа — гнётся, а не
  гофрируется («гармошка» — `../KINEMATICS.md`).
- **Что пишет расчёт** — лог, если что-то пошло не так.
- **Недавние прогоны** — вернуться к любому и сравнить.

## Прогоны гонять через лабораторию, а не мимо

Симуляцию можно запустить и напрямую (`python sim/reference2/run.py …`), но
тогда владелец не видит ни что считается, ни кадров. Правильно — через API:

```
curl -s -X POST http://127.0.0.1:8770/api/run -H 'Content-Type: application/json' \
  -d '{"variant":"reference2","layout":4,"frames":60,"grid":220,"particles":16000}'
```

Прогон появляется в списке, кадры видны по мере готовности. `frames` — до 60;
для разбора начала скрутки меньше 40 брать бессмысленно.

## Если что-то не так

- **Не открывается** — занят порт: `LAB_PORT=8790 ./lab.sh`.
- **Долго считает** — переключи подробность на «быстро».
- **Ошибка про gstaichi** — запускай именно `./lab.sh` (см. выше).
- **Мешает агентам** — прогон занимает 7 ядер; параллельные расчёты замедлят обоих.

Прогоны складываются в `runs/` и в репозиторий не попадают.
