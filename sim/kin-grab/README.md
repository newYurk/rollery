# kin-grab — четырёхфазная кинематика скрутки (вариант «кинематический захват края»)

Форк `../mpm-shell/run.py`. **Материалы, солвер (MLS-MPM + возврат по Хенки), растеризация 600×600 и
метрики не тронуты.** Переписана только кинематика: захват ближнего края + четыре фазы из
`../KINEMATICS.md`. Добавлена метрика `tail_outside` и ключ `--tuck`.

```
R=$(git rev-parse --show-toplevel)   # окружение локальное, в git его нет
source "$R/sim/.venv/bin/activate"
cd "$R/sim/kin-grab"
python run.py --layout 1 --grid 240 --particles 16000 --frames 10
```

Выходы в `out/`: `metrics_<L>.json`, `material_<L>.png/.npy`, `final_<L>.png`, `frames_<L>/*.png`
(включая по кадру на каждую смену фазы), `particles_<L>.npz` (финальные позиции частиц, класс,
ряд/столбец нори, J — для диагностики разрывов).

## 1. Геометрия и обозначения

Единица — T (толщина риса). Лист: нори `y ∈ [0, 0.12]`, `x ∈ [0, 38.7]`; рис `y ∈ [0.12, 1.12]`,
`x ∈ [0, 33.7]`; голый клапан нори `x ∈ [33.7, 38.7]`. Стол — `y = 0`. `Y_BED = W_NORI + T = 1.12` —
толщина входящего листа.

**Циновка** — дуга окружности радиуса `R` с центром `(x_c, R + y_lift)`; параметр дуги

```
θ = atan2( −(p_x − x_c), −(p_y − R − y_lift) )  ∈ [0, 2π)
точка дуги:  p(θ) = ( x_c − R·sin θ ,  R + y_lift − R·cos θ )
θ = 0 — низ, π/2 — сзади, π — верх, 3π/2 — спереди
```

Дуга живёт на `θ ∈ [θ_lo, θ_hi]`. Скорость границы (жёсткое тело + «раскручивание» ленты):

```
v_b(θ) = (v_c, Ṙ + ẏ_lift) + Ṙ·(−sin θ, −cos θ) + (v_spin − θ·Ṙ)·(−cos θ, sin θ)
```

при `v_spin = v_c` это качение без проскальзывания: `v_b(0) = 0`, `v_b(π) = (2·v_c, 0)`, `ω = v_c / R`,
центр едет со скоростью `ω·R`.

**Подъём циновки `y_lift`.** В фазе C круг циновки касается не стола, а **верха входящего листа**:
цель `y_lift = lift · Y_BED` (`--lift`, по умолчанию 1.0), нарастает за `T_LIFT = 8` и ограничена
скоростью `V_LIFT = 0.08`. Как только рис впереди кончился (меньше 1 % рисовых частиц лежит плашмя
перед роллом), цель падает до `W_NORI + 0.15`, чтобы циновка прижала голый клапан. В фазе D
`y_lift → 0`. Это и есть «ролл катится ПО листу, а не циновка по столу» из `KINEMATICS.md`: рисовая
постель проходит **под** роллом, а не сгребается перед ним.

**Нижний передний конец дуги** не опускается ниже `Y_FRONT_MIN = 0.30 T` (абсолютная высота, как
и просит `KINEMATICS.md`; ключ `--fronty`):

```
θ_hi ≤ 2π − arccos( 1 − (Y_FRONT_MIN − y_lift) / R )
```

При `--lift 1` низ самого круга и так стоит на `y = 1.12`, поэтому ограничение неактивно и дуга
доходит до собственного низа спереди — циновка прижимает входящий лист, но не может задеть стол.

## 2. Захват («пальцы»)

Захвачены частицы **нори** с начальным `x < GRAB_W = 0.9 T` (36 / 34 / 32 частицы на раскладках
1 / 2 / 4 при 16 000). Вес захвата **сглажен**, иначе полоса вырывается из листа:

```
w(x) = clamp( (GRAB_W − x) / (0.5·GRAB_W), 0, 1 )      # 1 при x ≤ 0.45, 0 при x ≥ 0.9
```

В G2P для захваченной частицы `v_p ← (1−w)·v_grid + w·v_grab`, `C_p ← (1−w)·C_p`.
Дополнительно на **сетке** задан диск-«палец» радиуса `R_FINGER = 0.65` с центром `g_c`, тоже с
размытым краем:

```
w_g = min( 1, (R_FINGER − |p − g_c|) / (0.35·R_FINGER) )
v_node ← (1 − w_g)·v_node + w_g·( v_g + ω_g × (p − g_c) )
```

(в текущей траектории `ω_g = 0` — диск только переносится).

**Траектория края (фазы A и B)** — половина эллипса:

```
P(θ) = ( x_p·(1 − cos θ) ,  y_0 + b·sin θ ),      θ: 0 → θ_end = π − 0.30
x_p  = s_fold / 2                      горизонтальная полуось
b    = min( x_p , h_top + 0.8 )        вертикальная полуось, h_top — верх самой высокой начинки
y_0  = W_NORI / 2 = 0.06
s_fold = tuck · s_fold_base,   s_fold_base = (конец зоны начинок) + 1 T,  либо 5 T на пустом листе
dθ/dt = v_g / |dP/dθ|,  |dP/dθ| = √(x_p²·sin²θ + b²·cos²θ),  v_g = 0.20·speed
```

Центр пальца — `P(θ)` плюс постоянный сдвиг до центроида захваченной полосы.

Ключевое свойство: `|P(θ) − (x_p, y_0)| ≤ x_p` при любом θ, то есть отрезок листа от сгиба до края
**никогда не растягивается**. При `b = x_p` (полуокружность) это точное вращение вокруг сгиба —
годится для пустого листа; при `b < x_p` отрезок провисает и лист **ложится** на начинки, а не сметает
их (§5, отступление 2).

Значения: L1 — `x_p = 2.50, b = 1.92`, длина дуги 6.39; L2 — `2.45 / 2.45`, 6.96;
L4 — `5.60 / 3.92`, 13.88.

## 3. Фазы

| фаза | что делает | конец |
|---|---|---|
| **A** подъём | захват едет по дуге `θ: 0 → π/2`; циновка выключена | `θ = π/2` |
| **B** перенос | та же дуга `θ: π/2 → θ_end`; лист ложится на начинки | `θ = θ_end` |
| **Btuck** подворот | захват идёт вниз, `v = (0, −0.5·v_g)`, пока `y > Y_TUCK = 0.67`; **здесь включается циновка** — «шапка» вокруг `θ = π` полушириной `0.5 → PHI_ROLL/2` за `T_WRAP = 12`, радиус по силе при `P_fold = 0.6·P_roll` | `y ≤ Y_TUCK` |
| **Bhold** удержание | `v = 0`, `T_HOLD = 5`, затем захват отпущен | по времени |
| **C** прокатка | `x_c += v_c·dt`, `v_c = 0.25·speed`; дуга `θ_hi = θ_f_max`, `θ_lo = max(0.15, θ_hi − PHI_ROLL)`, `PHI_ROLL = 5.5 рад ≈ 315°`; радиус по силе при `P_roll`; `y_lift` по §1 | впереди ролла нет несмотанного материала (`max x` частиц вне круга `R + 0.5` ближе `0.9·R` к `x_c`), либо `x_c ≥ 38.7 + 2` |
| **D_close** замыкание | `x_c ← ⟨x⟩`; радиус скачком до охватывающего `R = min( R_MAX, 1.8·R, max(R, 1.03·p₉₉.₅[ ((x−x_c)² + y²) / (2y) ]) )` — наименьший круг, касающийся стола, который накрывает хвост; дуга линейно закрывается до `[0, 2π]` за `T_CLOSE = 6`, давление `P_roll → P_press`, `y_lift → 0` | `T_CLOSE` |
| **D_press** прессовка | `[0, 2π]`, `P_press`, `V_RADIAL_PRESS = 0.12`; SDF круга (раскладка 5 — скруглённый квадрат) | `t ≥ 8` и (`|err| < 0.08` или `t ≥ 46`) |

Регулятор радиуса (как в `mpm-shell`): `F_t = P·R·(θ_hi − θ_lo)`, `err = (F_filt − F_t)/F_t`,
`Ṙ = V_RADIAL·clamp(err, −1, 1)`, `V_RADIAL = 0.075` (в фазе D — 0.12).

**Опорные давления снижены вдвое** против `mpm-shell`: `P_ROLL_REF 0.08 → 0.04`,
`P_PRESS_REF 0.16 → 0.08`. При старых значениях рис пережимается (`J` падает до 0.82–0.86), внешний
виток срывается и остаётся снаружи. `--press 2` воспроизводит прежнюю калибровку.

## 5. Что прошло и что нет

### Прошло

1. **Три дефекта первого прогона `mpm-shell` закрыты.**
   * *Намотка вокруг точки.* Ядро образуется подворотом: на `final_1.png` / `material_1.png` виден
     крючок нори в центре, спираль идёт от него наружу. `nori_turns` 3.25 → 2.94 (L1), 1.97 (L4).
   * *Рис сгребается перед катком.* Валика риса перед роллом больше нет (кадры `frames_*/…_C.png`).
     `rice_area_ratio` на L1 0.706 → 0.808; выброс `Rout` (5.73 при медиане 3.36 в первом прогоне)
     исчез: 3.81 при медиане 3.40.
   * *Хвост снаружи.* `tail_outside = false` на всех трёх раскладках: вне сглаженного контура
     остаётся 0.09 / 0.07 / 0.18 % частиц с максимальным выносом 0.57 / 0.38 / 0.82 T.
2. **Нори цела**: `nori_max_gap` 0.073 / 0.084 / 0.135 T при шаге частиц 0.049 / 0.052 / 0.056 и
   пороге 2.5 шага; `nori_torn = false`; `escaped = 0`; `stable = true` везде.
3. **Раскладка 4:** четыре начинки в ядре, циклический порядок сохранён
   (`core_order_by_phi = avocado → cucumber → tamago → salmon` — циклический сдвиг исходного
   `cucumber → tamago → salmon → avocado`), все четыре на `r = 0.72…2.79` при `Rout_median = 4.00`.
   **Диаметр — с оговоркой.** Измерено `2·Rout_median = 8.00 T`, `2·Rout = 9.51 T`. Ориентир
   `KINEMATICS.md` «⌀ ≈ 4,5–5 T» **как диаметр в T недостижим арифметически**: одного риса в срезе
   33.7 T², и круг такой площади уже имеет ⌀ 6.55 T. Число 4,5–5 — это **сантиметры** (ср.
   `reality-check.md`: футомаки ⌀ 4,7 см при слое риса 0,5 см = T). В сантиметрах при T = 5 мм
   получилось ⌀ **4.0 см** по медиане и **4.75 см** по максимуму — то есть по максимуму в ориентир
   попадает, по медиане на 0.5 см меньше (в ядре L4 остаётся пустота, п. 3 ниже).
4. **`--speed`, `--press`, `--tuck` монотонно и осмысленно меняют результат** (таблицы выше).
5. **Бюджет времени** — 19–21 с на прогон.

### Не прошло (и почему)

1. **`nori_turns` 1.0–1.2 (и старая цель 1.2–1.6) не достигается: L1 = 2.94, L2 = 2.53, L4 = 1.97.**
   Это не кинематика, а арифметика, и она проверяема **до** запуска. Лист наматывается спиралью
   Архимеда с шагом `h = T + W_NORI = 1.12` вокруг ядра площади `A_fill`:

   ```
   r0 = sqrt(A_fill / π)                 радиус ядра
   π·(R² − r0²) = h · L_SHEET            вся длина листа уложена в кольцо [r0, R]
   N = (R − r0) / h                      витков — ровно то, что считает лучевая метрика
   ```

   Это метрика `nori_turns_geom` в JSON. Она **не знает ничего о кинематике** — только длина листа,
   толщина риса и площадь начинок:

   | | L1 | L2 | L4 | L6 (диагностика) |
   |---|---|---|---|---|
   | `A_fill`, T² | 0 | 4.8 | 11.3 | 54.9 |
   | `nori_turns_geom` | 3.32 | 2.39 | 2.03 | 1.26 |
   | измерено | 2.94 | 2.53 | 1.97 | — (см. ниже) |

   Совпадение в пределах 0.4 витка (измеренное ниже на L1, потому что в ролле остаются пустоты —
   эффективный шаг больше 1.12). **Чтобы получить 1.0–1.2 витка при листе 38.7 T и рисе 1 T, нужно
   ядро `A_fill ≈ 55…65 T²`** — это и есть настоящий футомаки: ⌀ 5.5 см при T = 5 мм даёт обхват
   34.6 T ≈ длине листа, а начинок в нём ~15 см² = 60 T². У раскладок 1–4 начинок 0…11 T², то есть
   в 5–6 раз меньше; ролл выходит ⌀ 6.8–8.0 T с обхватом 21–25 T, и лист 38.7 T физически обязан
   лечь в 2–3 витка. *Ни один вариант кинематики этого не изменит* — цель в `KINEMATICS.md` задана
   для раскладок, которых в наборе нет.

   **Диагностическая раскладка 6** `futomaki-full-core` (тамаго 5.0×4.4, лосось 4.6×4.0,
   авокадо ⌀4.4×4.2 — `A_fill = 54.9 T²`) добавлена, чтобы это проверить прямо. Проверить **не
   удалось**: захват не поднимает лист над таким ядром, а тащит всю постель за собой (кадры
   `out/frames_6/*_B.png`: конец листа уезжает с x = 38.7 на x = 44), нори рвётся
   (`nori_max_gap = 14.3 T`), `stable = false`. Опыт с «второй рукой» (`--hold 1`, демпфирование
   горизонтальной скорости постели за зоной сгиба, пока край захвачен) уменьшает разрыв в 8 раз
   (`14.3 → 1.81 T`) и поднимает `rice_area_ratio` 0.474 → 0.555, но лист всё равно рвётся:
   `out/metrics_6h.json`. Причина в §5.4.2: при высоких начинках потолок `b = h_top + 0.8` перестаёт
   ограничивать дугу (`b = 6.32` при `x_p = 8.75`), отрезок листа идёт «дворником» сквозь стоящие
   начинки, а плечо сгиба `s_fold = 17.5 T` слишком велико для полосы захвата 0.9 T.
   *Вывод: чтобы свернуть ролл настоящей загрузки, нужен не этот захват, а либо две «руки»
   (вторая держит лист у дальнего края — `--hold` это только грубая заготовка), либо подворот
   в несколько приёмов.* `--hold` по умолчанию **выключен**: на L4 он мешает листу подаваться в
   сгиб и рвёт нори (`nori_torn = true`, `nori_turns` 1.97 → 2.83).

   *Вывод для калибровки стенда:* цель по `nori_turns` для раскладок 1/2/4 — **2.9 / 2.5 / 2.0**
   (или формула `nori_turns_geom`), а не 1.0–1.2; порог в `KINEMATICS.md` относится к роллу с
   полноценным ядром, и его надо либо переписать, либо добавить раскладку с `A_fill ≈ 60 T²`.

2. **`rice_area_ratio ≥ 0.90` не достигается: 0.808 / 0.798 / 0.735.** Метрика меряет площадь класса
   `rice` в карте среза, а она сверху ограничена средним якобианом: `ratio ≤ J_mean` (0.924 / 0.921 /
   0.925), плюс лента нори рисуется поверх риса и съедает ещё ~1.5–2 T² из 33.7. Отношение к этому
   потолку — новая метрика `rice_area_ratio_vs_J`: **0.874 / 0.866 / 0.795**. То есть при
   `J ≈ 0.925` потолок метрики ≈ 0.87, и L1/L2 сидят в 6–9 % от него. При `--press 0.5` на L1 —
   0.860 при `J = 0.946`. *Порог 0.90 достижим только если рис почти несжимаем; при
   `P_press/E_rice = 0.08` он сжимается на 7–8 %, и это правильная физика, а не потеря материала.*
   Остаток на L4 (0.737) — это пустота в ядре, п. 3.
3. **Раскладка 4: в ядре остаётся пустота** (`material_4.png`, пятно сверху-в-центре). При
   `P_press = 0.08` ролл встаёт в силовое равновесие на `R_mat = 4.57` с ~25 % пустот: «арка» из
   риса над начинками не схлопывается. При `--press 2` пустота закрывается (`Rout = 4.04`,
   `Rout_med = 3.84`, все четыре начинки на `r = 0.56…2.46`, хвоста нет), но рис пережимается
   (`ratio = 0.709`, `J = 0.879`). *Развилка для владельца: либо `P_press` выше и рис плотнее, либо
   ядро формировать не одним большим подворотом на `s_fold = 11.2 T`, а гуще (гребёнка/двойной
   подворот).*
4. **Отступления от буквы `KINEMATICS.md`** — все проверены экспериментом:
   1. *Полоса захвата 0.9 T вместо ≈ 0.5 T, с размытым краем и диском-пальцем.* Жёсткое предписание
      скорости 12–20 частицам вырывает полосу из листа: `nori_max_gap = 2.23 T`. Размытый захват на
      0.9 T даёт 0.07–0.13 T. Расширение до 1.6 T снова рвёт (1.60 T) — ядро становится слишком
      жёстким.
   2. *Дуга подворота — половина эллипса (`b = min(x_p, h_top+0.8)`), а не жёсткий поворот вокруг
      сгиба.* Натянутая полуокружность (`b = x_p`) работает на пустом листе, но на раскладке 4
      отрезок листа проходит как дворник сквозь стоящие начинки и расшвыривает их (тамаго улетает на
      `y ≈ 6`), а нори рвётся на 3.0–6.1 T. **У раскладки 2 `h_top + 0.8 = 3.92 > x_p = 2.45`, то
      есть ограничение неактивно и дуга всё ещё натянутая** — отсюда разрыв при `--tuck 1.3`. Просится
      второй потолок вида `b ≤ 0.8·x_p`.
   3. *Циновка включается в начале подворота (Btuck), а не в фазе B.* Если включить раньше, она
      прижимает лист под дальними начинками, тот перестаёт подаваться в сгиб, и нори рвётся ровно
      там. Трассировка разрыва по фазам при раннем включении (L4):
      `B: 0.13 → Btuck: 1.81 → Bhold: 3.70 → C: 4.09 T`; при позднем:
      `0.087 → 0.089 → 0.094 → 0.099 T`.
   4. *Дуга ≈ 315° (`PHI_ROLL = 5.5`) вместо ≈ 270°.* При 270° с поднятым кругом нельзя одновременно
      держать зад ролла и прижимать входящий лист спереди.
   5. *В фазе D добавлен «сбор»*: радиус скачком до охватывающего (99.5-й перцентиль), потом прижим.
      Без него замкнутая дуга просто не достаёт до хвоста, лежащего снаружи круга: он остаётся
      снаружи (`tail_outside_frac` до 0.087).
   6. *Опорные давления снижены вдвое* (см. §3).
   7. Ограничение «дуга не ниже 0.3 T впереди ролла» выполняется буквально
      (`Y_FRONT_MIN = 0.30`, ключ `--fronty`), но работает только вместе с подъёмом круга: при
      `--lift 0` низ круга лежит на столе, дуга спереди действительно доходит до 0.3 T, врезается в
      рисовую постель (её верх 1.12 T) и валик риса возвращается.

## 6. Ключи командной строки

```
--layout 1|2|3|4|5     раскладка (6 — диагностическая, «полное ядро», §5.1; не из пяти контрольных)
--speed  s             v_c = 0.25·s (центр циновки в фазе C), v_g = 0.20·s (захват в A/B)
--press  p             P_roll = 0.04·p, P_press = 0.08·p, P_fold = 0.6·P_roll
--tuck   0.6..1.3      s_fold = tuck · s_fold_base
--lift   0..1.2        подъём круга циновки в долях Y_BED (1 = ролл катится по листу)
--hold   0..2          «вторая рука»: демпфирование горизонтальной скорости постели за зоной
                       сгиба, пока край захвачен (0 = выкл., по умолчанию; 1 = 1.5 % за подшаг).
                       Нужна только тяжёлому ядру (раскладка 6); на 1/2/4 вредит — см. §5.1
--fronty y             высота нижнего переднего конца дуги, T (по умолчанию 0.30, минимум 0.30)
--grid N               ~N² узлов, аспект по домену; 240 → 469×122
--particles N          целевое число частиц
--frames N             отладочные кадры (+ по кадру на каждую смену фазы)
--window W --tag S --out DIR
```

## 7. Новые метрики в `metrics_<L>.json`

```
tail_outside               bool   — доля частиц дальше 0.3 T снаружи контура превышает 0.2 %
tail_outside_particles     int    — сколько таких частиц
tail_outside_nori          int    — сколько из них нори (то есть непри­жатый клапан, а не крошки риса)
tail_outside_max_excess_T  float  — максимальный вынос за контур, T
tail_outside_frac, tail_tol_T
Rout_median_T                     — медиана по 36 лучам (устойчивее максимума)
nori_turns_geom            float  — априорное число витков спирали, только из L_SHEET, T и A_fill
rice_area_ratio_vs_J       float  — rice_area_ratio, делённая на rice_J_mean (потолок метрики)
core_order_by_phi                 — порядок начинок вокруг ядра по возрастанию φ
tuck, grab{...}, phases{...}, mat{...}
```

Контур для `tail_outside` — те же 36 лучей, сглаженные бегущей медианой по 5 точкам, чтобы хвост,
торчащий на двух-трёх лучах, не поднял контур сам под себя.
