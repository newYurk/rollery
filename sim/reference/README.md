## 1. Метод

**Солвер.** MLS-MPM, явный, аффинный перенос (APIC), квадратичный B-сплайн (шаблон 3×3),
плоская деформация. Сетка выводится из `--grid` и аспекта домена: `--grid 240` → 469×122 узлов,
`dx = 0.1066`, `dt = CFL·dx/c_max` с `CFL = 0.3` (`dt ≈ 0.0071…0.0078`). Домен
`x ∈ [−2, 48]`, `y ∈ [−0.4, 12.6]`. 23–32 тыс. шагов на прогон, **19–27 с** на M4 Max (CPU,
gstaichi 4.6).

**Единицы.** `T = 1` — толщина слоя риса (≈ 5 мм в жизни), `ρ_рис = 1`, `E_рис = 1`,
единица времени `= T/√(E/ρ)`. Гравитация 0.01 (в этих единицах она почти не работает —
форму держат циновка и жёсткость материалов, как и в жизни).

**Определяющее соотношение.** Упругость Хенки (логарифмическая деформация) с возвратным
отображением по фон Мизесу на девиатор — пластичность **объём сохраняет**:

```
F ← (I + dt·C)·F,   F = U·diag(σ₀,σ₁)·Vᵀ,   e = ln σ
e_m = (e₀+e₁)/2,  d = (e₀−e₁)/2
если 2μ|d| > τ_y :  d ← ±τ_y/(2μ),  F ← U·diag(e^{e_m+d}, e^{e_m−d})·Vᵀ     (перенастройка)
τ = U·diag(2μ e₀ + λ tr e,  2μ e₁ + λ tr e)·Uᵀ,      J = exp(e₀+e₁)
```

Следствие, важное для метрик: `J` меняется **только упруго**, поэтому
`Σ(vol·J)/Σ(vol) ≈ exp(−P/(λ+μ))` — сохранение объёма задаётся давлением прижима и модулем
объёмного сжатия, а не «потерей материала» (§5.2).

**Растеризация.** Каждая частица — диск радиуса `0.6·h_p` своего класса, окно 12 T вокруг
центроида → карта 600×600 (`material_*.png/.npy`), из неё считаются лучевые метрики.

## 1.1 Параметры материалов

`(E, ν, τ_y, ρ)`; `τ_y = 10⁹` означает «упругий, не течёт»; `μ = E/2(1+ν)`, `λ = Eν/((1+ν)(1−2ν))`.

| материал | E | ν | τ_y | ρ | смысл |
|---|---|---|---|---|---|
| рис | 1.0 | 0.35 | 0.03 | 1.0 | мягкий, легко течёт — задаёт масштаб всех остальных |
| нори | 25.0 | 0.30 | 10⁹ | 2.0 | жёсткая на растяжение, мягкая на изгиб (полоса тонкая) |
| лосось | 3.0 | 0.40 | 0.15 | 1.0 | мягкий, течёт |
| огурец | 15.0 | 0.30 | 10⁹ | 1.0 | твёрдый, форму держит |
| тамаго | 10.0 | 0.35 | 10⁹ | 1.0 | твёрдый |
| авокадо | 4.0 | 0.40 | 0.15 | 1.0 | мягкий, течёт |
| креветка | 6.0 | 0.35 | 10⁹ | 1.0 | (в контрольных раскладках не используется) |

Трение: `μ_стол = 0.4` (сепарабельная стенка с кулоновским трением), `μ_циновка = 2.0`
(фактически липкая, пока прижата).

## 1.2 Геометрия листа

Лист: нори `y ∈ [0, 0.12]`, `x ∈ [0, 38.7]`; рис `y ∈ [0.12, 1.12]`, `x ∈ [0, 33.7]`;
голый клапан нори `x ∈ [33.7, 38.7]`. Стол — `y = 0`. Толщина входящего листа
`Y_BED = T + w = 1.12`.

Длина листа 38.7 T взята **из стенда**, а не выдумана: стенд выводит длину из числа оборотов,
`L = r₀θ + Pθ²/4π`, `θ = 2π·turns`, `P = T + w`, `r₀ = 0.25`; для базы «суши» это даёт 38.7 при
`turns = 3.10` (`../KINEMATICS.md`, «Геометрия баз»).

**Победила `kin-grab`.** Решающее — подворот: у `kin-mat` на раскладках 4 и 5 ближний край
остаётся снаружи (`r_near` 0.85 и 0.87 — это внешний виток, а не крючок в ядре), то есть
кинематика перестаёт быть подворотом ровно там, где начинки тяжёлые. Плюс лучше согласие с
формулой слоёв, круглее и быстрее.

**Пересажено из `kin-mat`** (проигравшей) — четыре вещи, все дали измеримое улучшение:

1. **Циновка как архимедова спираль, а не поднятый круг.** `rb(θ) = R − p·θ/2π`, шаг
   `p = ` толщина того, что ещё лежит впереди (`Y_BED = 1.12` на рисе, `w + 0.15` на голом
   клапане). Нижне-передняя ветвь спирали входит в контакт ровно на верху постели и дальше
   только поднимается, поэтому постель проходит **под** роллом. Это заменило костыли `kin-grab`
   (`--lift` и обрезку дуги `Y_FRONT_MIN`) одной геометрией. Ключ `--pitch` (1 = точно по
   толщине, 0 = обычный круг, который пашет рис).
   *Здесь доделано то, что `kin-mat` записала себе в ограничения (её §7):* шаг переключался по
   `x_c` (рис / клапан), а не по фактической толщине впереди. Теперь, если **впереди ролла стоит
   начинка** (частицы класса начинки в полосе `x ∈ [x_c + 1.05R, x_c + 2.2R]`, 98-й перцентиль
   высоты выше `Y_BED + 0.5`), шаг поднимается до её высоты + 0.3, не выше `PITCH_MAX = 3.2`.
   Раскладка 3 (лосось в середине листа): доля материала вне контура 2.7 % → 1.8–2.2 %. Мерить
   **все** частицы в полосе, а не только начинки, нельзя — на голом листе шаг убегает в
   `PITCH_MAX` и ролл наматывается слишком туго (L1: витков 2.47 → 3.5, сохранение 0.959 → 0.933,
   `Rout_max` 3.66 → 4.69); обе отвергнутые версии описаны комментарием в коде.
2. **Правило зоны сгиба.** В ядро заворачиваются только начинки у ближнего края: первая должна
   начинаться ближе `FOLD_REACH = 5 T` от края, следующая — не дальше `FOLD_GAP = 2.5 T` после
   предыдущей; `s_fold = (конец зоны) + 1 T`, не дальше `0.45·L`. Без этого правила раскладка 3
   (лосось в середине листа) складывала лист пополам — чего повар не делает и чего нет в стенде.
3. **Подъём кольца при прессовке** `LIFT_PRESS = 0.25`: в фазе D замкнутое кольцо приподнято над
   столом, иначе прессовка выдавливает рис вбок в клин «кольцо–стол» (у `kin-grab` это давало
   плёнку риса под роллом).
4. **Семейство метрик сохранения** `Σ(vol·J)/Σ(vol)` отдельно по классам — вместо «доли риса в
   карте», которая систематически занижена растеризацией.

Своё, добавленное здесь: `--seed`, уточнённая формула слоёв (§5.1), `layers_predicted*` и
`conservation*` в JSON, `rice_under_filling_T` с проходом сквозь дырки растра, раскладки 3 и 5,
отдельный бюджет прессовки для квадрата, захват нори в «сборе» кольца, ужатый выход из фазы C.

## 3. Кинематика по фазам

Циновка — параметрическая спираль, касающаяся стола в точке схода `x_c`; `R` — радиус там,
`p` — шаг, `y_lift` — подъём кольца, дуга живёт на `θ ∈ [θ_lo, θ_hi]`:

```
C(t)  = (x_c,  R + y_lift)
rb(θ) = R − p·θ/(2π)                                   θ отсчитывается от точки схода
P(θ)  = C + rb(θ)·(−sin θ, −cos θ)                     θ=0 стол, π/2 зад, π верх, 3π/2 перёд
v_b(θ) = (v_c, Ṙ + ẏ_lift) + Ṙ·(−sin θ, −cos θ)
         + ( v_spin·rb/R − unroll·θ·Ṙ )·(−cos θ, sin θ)
```

Множитель `rb/R` делает вращение жёстким; при `v_spin = v_c` получается `v_b(0) = 0` —
качение без проскальзывания, `ω = v_c/R`. Контакт ставится на узлах сетки с
`r − rb ∈ (−0.5dx, 3dx)`, нормаль `n = (sin θ, cos θ)`, кулоновское трение `μ_циновка = 2`.

**Захват («пальцы»).** Частицы нори с `x < GRAB_W = 0.9 T` получают предписанную скорость с
размытым весом `w(x) = clamp((0.9 − x)/0.45, 0, 1)`; в G2P `v_p ← (1−w)v_сетки + w·v_захвата`.
Плюс на сетке жёсткий диск радиуса `R_FINGER = 0.65` вокруг центроида полосы, тоже с размытым
краем. Полоса 0.9 T, а не 0.5 T как в спецификации: при жёстком предписании 12–20 частицам
полоса **вырывается** из листа (`nori_max_gap` 2.2 T против 0.06–0.13 T сейчас).

**Траектория края (фазы A и B)** — половина эллипса вокруг точки сгиба:

```
P_g(θ) = ( x_p(1 − cos θ),  y₀ + b·sin θ ),     θ: 0 → θ_end = π − 0.30
x_p = s_fold/2,   b = min( 0.8·x_p , h_top + 0.8 ),   y₀ = w/2 = 0.06
dθ/dt = v_g/|dP_g/dθ|,   |dP_g/dθ| = √(x_p² sin²θ + b² cos²θ),   v_g = 0.20·speed
```

`|P_g(θ) − (x_p, y₀)| ≤ x_p` при любом θ — отрезок листа от сгиба до края **никогда не
растягивается**. Потолок `b ≤ 0.8·x_p` (это и есть «второй потолок», который просила `kin-grab`
в своём §5.4.2) держит дугу провисшей: натянутая полуокружность `b = x_p` идёт «дворником»
сквозь стоящие начинки и рвёт нори при `--tuck 1.3`.

| фаза | что делает | конец |
|---|---|---|
| **A** подъём | захват едет по дуге `θ: 0 → π/2`, циновка выключена | `θ = π/2` |
| **B** перенос | та же дуга `θ: π/2 → θ_end`; лист **ложится** на начинки | `θ = θ_end` |
| **Btuck** подворот | захват вниз, `v = (0, −0.5 v_g)`, до `y ≤ Y_TUCK = w + 0.55T = 0.67`; **включается циновка** — «шапка» вокруг `θ = π` полушириной `0.5 → PHI_ROLL/2 = 2.75` за `T_WRAP = 12`, давление `P_fold = 0.6 P_roll` | `y ≤ Y_TUCK` |
| **Bhold** удержание | `v = 0`, `T_HOLD = 5`, затем захват отпущен | по времени |
| **C** прокатка | `x_c += v_c dt`, `v_c = 0.25·speed`; дуга полная `[0, 2π]`, шаг спирали `p → Y_BED`, потом `→ w + 0.15` на клапане, а если впереди стоит начинка — до её высоты (§2, п. 1); скорость изменения `≤ V_PITCH = 0.08`; давление `P_roll` | впереди ролла нет несмотанного материала (`max x` частиц вне спирали ближе `C_EXIT_FRAC·R = 0.55R` к `x_c`), либо `x_c ≥ 40.7` |
| **D_close** замыкание | «сбор»: `x_c ← ⟨x⟩`, радиус однократно раскрывается до охватывающего (§4, `gather_R`), дуга уже `[0, 2π]`, шаг `p → 0`, давление `P_roll → P_press` за `T_CLOSE = 6` | `T_CLOSE` |
| **D_press** прессовка | кольцо поднято на `LIFT_PRESS = 0.25`, `P_press`, `V_RADIAL_PRESS = 0.12`; SDF круга, для раскладки 5 — скруглённого квадрата (`CORNER_R = 0.6`), для него сбор пересчитывается под квадрат | `t ≥ 8` и (`|err| < 0.08` или `t ≥ 46`; для квадрата `≥ 100`) |

**Регулятор радиуса.** `F_t = P·L_контакта` (`L = R(θ_hi − θ_lo)` для круга, `8R` для квадрата),
`err = (F_фильтр − F_t)/F_t`, `Ṙ = V_RADIAL·clamp(err, −1, 1)`, `V_RADIAL = 0.075`
(в фазе D — 0.12), `R ∈ [0.8, 8.0]`.

**Опорные давления** снижены вдвое против исходного `../mpm-shell`: `P_roll = 0.04`,
`P_press = 0.08` (в единицах `E_рис`) при `--press 1`. При 0.08/0.16 рис пережимается,
`J` падает до 0.86 и внешний виток срывается.

## 3.1 Входы «руки»

| ключ | что меняет | наблюдаемая реакция |
|---|---|---|
| `--speed s` | `v_c = 0.25s` (центр в фазе C), `v_g = 0.20s` (захват в A/B) | быстрее — рыхлее: радиус циновки +9 %, `J` ближе к 1, витков не больше |
| `--press p` | `P_roll = 0.04p`, `P_press = 0.08p`, `P_fold = 0.6 P_roll` | сильнее — плотнее и меньше; L4: `Rout_med` 4.01 → 3.86, витков 2.19 → 2.42, сохранение 0.954 → 0.933. Слабее (0.6): сохранение **0.974**, `Rout_med` 3.90 |
| `--tuck 0.6…1.3` | `s_fold = tuck · s_fold_base` | двигает начинку из центра наружу и вращает крючок; на L2 `r` тамаго 0.15 → 0.99 → 1.50 T. На четырёх начинках безопасно 0.85…1.3 |
| `--pitch 0…1.2` | шаг спирали в долях толщины листа впереди | 0 — обычный круг, пашет рис перед роллом (это и был главный дефект первого прогона) |
| `--hold 0…2` | «вторая рука»: демпфирование горизонтальной скорости постели за зоной сгиба, пока край захвачен | нужна только очень тяжёлому ядру; на 1–5 **вредит** (лист перестаёт подаваться в сгиб). По умолчанию выключено |
| `--seed N` | зерно джиттера частиц при засеве | разброс между зёрнами: витков ±0.06…0.11, `Rout_med` ±0.04, сохранение ±0.001 |

## 4. Как запускать

```
python run.py --layout 1|2|3|4|5   раскладка (6 — диагностическая «полное ядро», не контрольная)
              --speed 1.0 --press 1.0 --tuck 1.0 --pitch 1.0 --hold 0.0
              --seed 1
              --grid 240           ~N² узлов, аспект по домену
              --particles 16000
              --frames 8           отладочные кадры (+ по кадру на смену фазы); 0 — без кадров
              --window 12 --tag S --out DIR
python table.py [DIR]              таблица §5 из metrics_*.json
```

Прогон на CPU параллельный, порядок сложения в P2G не фиксирован, поэтому **повторный запуск с
тем же `--seed` даёт не тот же результат**: `nori_turns` ±0.1, `Rout` ±0.05, доля хвоста ±0.005.
`--seed` меняет только засев частиц; разброс по зёрнам того же порядка.

### 5.1 Число слоёв: буквальная формула и уточнённая

Буквальная формула из `../KINEMATICS.md` (правка от 26.08.2026) — та, по которой сверяется стенд:

```
площадь = рис (L − клапан)·T + нори L·w + начинки
Rout  = √(площадь/π),   Rcore = √(s_fold·(T+w)/π),   слоёв = (Rout − Rcore)/(T+w)
пересечений лучом = слоёв + 1        (плюс нори самого подворота)
```

Референс даёт по ней невязку **−0.12…−1.22 витка**, всегда в минус, и тем больше, чем больше
начинок в зоне сгиба (пустой лист −0.12, четыре начинки −0.57, переполнение −1.22). Это не
«недокрут»: буквальная запись роняет два члена, оба — чистая бухгалтерия площадей, оба без
всякой кинематики.

1. **Начинки зоны сгиба лежат в ядре, а не в кольце обёртки.** Их площадь входит в `Rout`, но не
   в `Rcore`, и потому засчитывается в кольцо второй раз. Правильно — `Rcore² ← Rcore² + A_fold/π`.
2. **Лист толщиной `h` нельзя согнуть в нулевой радиус.** У сгиба остаётся полость радиуса ≈ `h`,
   то есть `Rcore² ← Rcore² + h²`. Это ≈ 0.35 витка.

```
Rcore_core   = √( (s_fold·h + A_fold) / π )
Rcore_hollow = √( Rcore_core² + h² )                 h = T + w = 1.12
слоёв_core   = (Rout − Rcore_hollow) / h
```

Невязка к уточнённой формуле — строка «Δ к уточнённой» в таблице. **Это и есть проверка
критерия 1.** Полость сгиба — не подгонка, а измеримая вещь: при `--press 1.5` на раскладке 4 она
схлопывается, и число витков уходит от уточнённой формулы обратно к буквальной
(2.19 → 2.42 при `Rout_med` 4.01 → 3.86, `crossings` буквальная 2.76). То есть буквальная формула
описывает **полностью уплотнённый** ролл с монолитным ядром, уточнённая — ролл, скрученный
рукой при `--press 1`. Обе честные, отличаются на полость.

**Для сравнения со стендом** (правка 3 задания): метрики самой обёртки — число витков, клапан,
положение шва — идут отдельной строкой и **под них параметры не тянутся**. Стенд режет лист
ровно по обхвату (это выбор правильного размера листа, а не выдумка), референс держит целый лист
с клапаном 5 T снаружи. Сравнивается рис, начинки, устройство ядра, форма бугра и реакция на руку.

### 5.2 Сохранение: что мерить и чего ждать

Правильная мера — `Σ(vol_p·J_p)/Σ(vol_p)`. Она равна средневзвешенному `J`, а `J` в этой модели
меняется **только упруго** (пластичность фон Мизеса объём сохраняет), поэтому

```
conservation ≈ exp( −P_press / (λ + μ) )
λ_рис + μ_рис = 1.234   при  E = 1, ν = 0.35   (плоская деформация)
```

При `--press 1` (`P_press = 0.08`) это даёт для риса `exp(−0.0648) = 0.937`; измеренное
`conservation_rice` 0.933–0.956, полное — 0.952–0.963 (нори почти несжимаема, `J ≈ 0.99`).

**Порог «≥ 0.97» — это утверждение о давлении прижима, а не о кинематике.** Он достигается при
`--press ≈ 0.5…0.6`: раскладка 4 при `--press 0.6` даёт `conservation = 0.9735`
(`out_probe/metrics_4_p06.json`), при `--press 1.5` — 0.9327. Сжатие риса на 4–6 % при
`P/E = 0.08` — правильная физика зернистой постели, а не потеря материала: `escaped = 0` во всех
прогонах, вне контура остаётся ≤ 0.04 % частиц на раскладках 1, 2, 4.

`rice_area_ratio` (доля класса «рис» в карте среза, 0.74–0.81) — **артефакт растеризации**, не
метрика потерь, и в таблице стоит справочно: диск фиксированного радиуса перестаёт покрывать
плоскость, когда частицы разъезжаются сдвигом, плюс лента нори рисуется поверх риса. Контроль:
на **начальном** состоянии та же растеризация даёт 33.70 T² при истинных 33.7.

### 5.3 Порядок начинок в ядре

Ожидать надо **инверсию**: ближняя половина постели ложится в ядро перевёрнутой — это прямое
следствие подворота и ровно то, что рисует стенд (`../../docs/reality-check.md`, п. 2).
Поэтому в таблице ядра сравнивать надо циклический порядок по φ, а не буквальный порядок по x.

## 6. Что не закрыто

Отсортировано по важности для калибровки стенда.

1. **Раскладка 3: доля вне контура 1.8–2.2 %, отдельный кусок в 3.5 T от контура.** Ролл, наезжая на начинку, стоящую
   посреди листа, всё ещё сгребает часть постели, и она остаётся лежать перед ним куском
   (`out/material_3.png`, доля справа-внизу). Правило «шаг спирали по высоте начинки впереди»
   (§2, п. 1) убрало часть — 2.7 % → 1.8 %, — но не всё. Следующий шаг: считать шаг не по
   перцентилю высоты в полосе, а по фактической высоте материала в точке касания нижне-передней
   ветви (нужен проход по сетке внутри ядра, а не numpy снаружи).
2. **Раскладка 5: клапан не прижат — 88 частиц нори снаружи (0.6 %), вынос до 1.2 T, форма выходит
   скруглённо-треугольной, а не квадратной.** Силовая цель квадрата — `P·8R` по всему периметру,
   но недозаполненный квадрат касается материала лишь частью грани, поэтому `F` не догоняет цель,
   радиус ползёт вниз весь бюджет (`T_PRESS_MAX_SQ = 100` вместо 46 — уже поднято) и клапан
   выдавливается в угол. Правильно — считать цель по **фактической длине контакта**, а не по
   периметру; это требует накопления длины контакта в ядре `substep`.
3. **Раскладка 4 — самый некруглый ролл и нестабильная пустота в ядре.** `Rout_min` 2.93 против
   медианы 4.01 и максимума 4.51: справа бугор, снизу доля (`out/material_4.png`). Арка из риса
   над четырьмя начинками при `P_press = 0.08` схлопывается **не в каждом прогоне**: в одних
   `rice_under_filling_T` у тамаго 1.08, в других 0 при `outer_hit = "bg"` (то есть под тамаго
   пустота). При `--press 1.5` закрывается устойчиво (`Rout_med` 4.00 → 3.86, витков 2.19 → 2.42),
   но рис пережимается (сохранение 0.954 → 0.933). Развилка для владельца: либо давление выше,
   либо ядро формировать не одним подворотом на `s_fold = 11.2 T`, а гуще (гребёнка/двойной
   подворот).
4. **Сохранение ≥ 0.97 достигается только при `--press ≈ 0.5…0.6`** (§5.2). При дефолтном
   `--press 1` это 0.952–0.963. Это не дефект кинематики, а калибровка давления: решать владельцу,
   какой прижим считать «настоящим».
5. **Буквальная формула слоёв не выполняется и выполняться не может** (§5.1): невязка
   −0.12…−1.22 витка. Уточнённая (ядро + полость сгиба) сходится в пределах ±0.25 на четырёх раскладках из
   пяти; на раскладке 4 остаётся +0.30 — ровно за счёт пустоты и некруглости п. 3.
6. **Прогон не воспроизводится побитово.** gstaichi на CPU складывает в P2G атомарно, порядок
   редукции меняется от запуска к запуску: `nori_turns` ±0.1, `Rout` ±0.05, доля хвоста ±0.005.
   `--seed` управляет только засевом частиц; разброс по зёрнам того же порядка. Все выводы выше
   проверены на разбросе, но одиночные числа в таблице сравнивать с точностью до третьего знака
   нельзя.
7. **Настоящее футомаки (площадь начинок ≈ 55–60 T²) этой кинематикой не сворачивается.**
   Диагностическая раскладка 6 (`A_fill = 54.9 T²`, здесь не прогонялась — измерено в
   `../kin-grab`, её §5.1, на той же кинематике): захват не поднимает лист над таким ядром, а
   тащит всю постель за собой, нори рвётся (`nori_max_gap` 14.3 T). «Вторая рука» (`--hold 1`)
   уменьшает разрыв в 8 раз, но не спасает. Нужен либо второй захват у дальнего края, либо подворот в несколько приёмов.
   Пять контрольных раскладок несут 0…11 T² — им это не мешает, но целиться в «один оборот нори»
   на них бессмысленно (§5.1).
8. **`rice_area_ratio` смещена вниз на ≈ 15 %** в деформированном состоянии (§5.2). В таблице
   стоит справочно; для сравнения стенда с референсом использовать `conservation*`,
   `rice_outside_contour_frac` и IoU карт 600×600.
